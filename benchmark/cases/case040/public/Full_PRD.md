# Velnora Full Product Requirements

Velnora is a console user interface library for building interactive applications from reusable text, controls, layouts, displays, and event handling.

### FP-01: Text encoding and display geometry

- Unicode text is displayed using the selected global encoding, initially the host locale's preferred encoding. Already encoded text can pass through without being decoded and re-encoded. Unicode conversion supports ASCII, UTF-8, ISO-8859, EUC-JP restricted to JISX 0208, EUC-KR, EUC-CN, GB2312, GBK, BIG5, and UHC. CN-GB and EUC-TW restricted to plane 1 support already encoded text and double-byte display geometry; Unicode conversion is not provided for these two encoding names.

- Text measurement and clipping use screen columns: printable ASCII and ordinary narrow letters occupy one column, East Asian wide characters occupy two, and combining marks add no columns to their base. Emoji joined sequences, emoji with skin-tone modifiers, and paired regional indicators occupy two columns and remain whole when traversing or clipping grapheme clusters. Clipping through a wide glyph leaves blank space in the exposed partial cell. Within the supplied text boundaries, column lookup returns the furthest complete-character boundary that does not exceed the requested column, together with the columns consumed. These geometry rules apply to Unicode text and valid UTF-8 encoded text; other supported single-byte encodings use one column per byte and supported East Asian double-byte characters use two columns.

- For non-UTF-8 output, callers can supply single-column character replacements for characters the selected encoding cannot represent. Both a key and its replacement must be one character; a key must occupy one column and must not be printable ASCII, and a replacement must be printable ASCII or a DEC graphic character. Other entries are refused as invalid replacements. DEC graphics translation takes precedence, and UTF-8 output does not use this replacement table. Unrepresentable characters without an applicable replacement are replaced by one printable nonspace ASCII character. In byte-oriented text markup, only printable ASCII replacements are available. Replacing the collection replaces all previous entries; an empty collection clears it. An invalid entry leaves the previous collection intact, and later changes to the supplied collection do not alter the registered replacements.

- For non-UTF-8 text, the DEC graphic repertoire comprises a solid vertical rectangle, diamond, checkerboard, degree sign, plus-minus sign, less-than-or-equal and greater-than-or-equal signs, pi, not-equal sign, pound sign, middle dot, visible symbols for horizontal tab, form feed, carriage return, line feed, newline and vertical tab, the four square line corners, crossing lines, horizontal and vertical lines, horizontal lines at four additional scan heights, and the four three-way line junctions. These graphics remain distinguishable when represented through the terminal graphic character set.

### FP-02: Widget sizing and canvas composition

- Widgets support their declared sizing modes: box widgets render within supplied columns and rows, flow widgets calculate rows for a supplied width, and fixed widgets report their natural dimensions. A packed size request on a flow widget reports the width its content actually uses, clipped to the supplied width, together with the rows needed at that width. Rendering exposes the resulting text, dimensions, display attributes, and optional cursor position. Space added around a text label or by canvas padding is blank and has no source-text attribute; an enclosing attribute mapping can style it. A request using a sizing mode the widget does not support is refused as incompatible sizing.

- Callers can compose rectangular canvases side by side, vertically, or with a foreground covering part of a background. Cropping, padding, and translation preserve the retained text and attributes and adjust cursor coordinates to the resulting rectangle; a cursor in a vertically removed row is absent.

- Changes to widget content, appearance, or focus are reflected in subsequent rendering, including when the changed widget is nested inside a composition.

- Application-defined widgets can participate in rendering, sizing, focus, keyboard input, mouse input, and cursor positioning. A key the recipient does not handle remains available to its enclosing widget or application.

- Plain and captured-text labels, buttons, check boxes, radio controls, drop-downs, and tree-node labels support flow and fixed sizing. Editors, dividers, and progress indicators support flow sizing. Large lettering supports fixed sizing. Character fills, bar charts, chart scales, and embedded terminals support box sizing. Grids support flow and fixed sizing. Attribute mappings, borders, disabling wrappers, placeholders, and pop-up launchers preserve the sizing modes of their child.

### FP-03: Display attributes and hyperlinks

- Callers can associate foreground, background, and text effects with named palette entries or directly with text. Color modes are monochrome, 16 colors, 88 colors, 256 colors, and 24-bit color; direct attributes allow 256 colors by default. The basic colors are black, dark red, dark green, brown, dark blue, dark magenta, dark cyan, light gray, dark gray, light red, light green, yellow, light blue, light magenta, light cyan, and white; terminal default colors are also available. A description requiring colors unavailable in its selected mode, an unrecognized color description, or an unsupported color mode is refused as invalid attributes.

- Text effects comprise bold, faint, italics, underline, blink, standout, and strikethrough. Nested attributed text preserves the text order and uses inner attributes over outer attributes. Foreground and background can independently inherit from the enclosing attribute, and both inherit by default for direct attributes. An attribute inheriting a color also inherits effects it has not explicitly set or removed. An attribute explicitly specifying both colors does not inherit enclosing effects. Remaining inheritance resolves against the default palette entry. Repeating an effect declaration or declaring the same effect both set and removed is refused as invalid attributes.

- An attribute mapping can restyle a widget's text and blank area without changing its content. A separate focus mapping applies while focused. Replacing a palette entry changes subsequent drawing that refers to that entry.

- Text runs can carry a hyperlink target and optional link identity. Nested runs can inherit a link, replace it, or explicitly remove it without altering their characters. Link targets and identities containing characters outside printable ASCII are refused as unsafe hyperlink data. An empty target explicitly removes a link. A nonempty identity supplied with an empty target, or an identity containing a colon or semicolon, is refused as invalid hyperlink data. Targets longer than 2083 characters and identities longer than 250 characters are refused as too long.

- Callers can select an indexed color, a red-green-blue color, or a grayscale intensity. Indexed colors range from zero through one less than the selected palette size in 88-color and 256-color modes; true-color mode accepts indices from zero through 255. The first sixteen indices follow the listed basic-color order. Their red, green, and blue intensities are respectively: black, zero on all channels; dark red, dark green, and dark cyan, 205 on their named channels and zero on the others; brown, red and green at 205 and blue at zero; dark blue, blue at 238 and the others at zero; dark magenta, red and blue at 205 and green at zero; light gray, 229 on all channels; dark gray, 127 on all channels; light red, light green, yellow, light magenta, light cyan, and white, 255 on their named channels and zero on the others; light blue, red and green at 92 and blue at 255. Later indices enumerate the color cube with blue changing fastest, then green, then red, followed by the non-endpoint grayscale intensities in increasing order. Full-resolution true color preserves each supplied red, green, and blue component from zero through 255. Compact red-green-blue input expresses each component on a sixteen-level scale from zero through fifteen. In indexed modes, each such level denotes the corresponding fraction of full intensity and selects the nearest available palette component independently: the levels are 0, 95, 135, 175, 215, and 255 for 256 colors, and 0, 139, 205, and 255 for 88 colors. Full-resolution red-green-blue input in indexed modes chooses the same color for each component interval of sixteen consecutive values as the corresponding compact level. Compact red-green-blue input in true-color mode selects the same intensities as in 256-color mode. Grayscale input accepts an integer percentage from zero through 100 or an integer intensity from zero through 255; percentages denote the corresponding fraction of full intensity rounded to the nearest intensity. Grayscale chooses the nearest available gray, with ties favoring the brighter choice. The available intensities are black at zero and white at 255, plus 8, 18, 28, 38, 48, 58, 68, 78, 88, 98, 108, 118, 128, 132, 148, 158, 168, 178, 188, 198, 208, 218, 228, and 238 in 256-color mode, or 46, 92, 115, 139, 162, 185, 208, and 231 in 88-color mode. True-color grayscale uses the same intensities as 256-color grayscale. Monochrome attributes accept text effects and terminal-default or inherited colors, rather than explicit colors.

- Palette entries can provide separate basic-color, monochrome, and high-color appearances. Unspecified high-color appearances use the basic appearance, and unspecified monochrome appearance has no effects. In 88-color display, if either high-color foreground or background is supplied as an index above fifteen, both colors use the basic appearance instead. Callers can copy an already registered entry under another name; the copy retains the appearance at the time of copying, and copying an unknown name is refused as invalid palette data.

### FP-04: Notifications and listener lifetime

- Applications can declare notifications, attach listeners with application context, and emit a notification with event data. Emission calls listeners in connection order and reports handled if at least one listener returns an affirmative result; this does not prevent remaining listeners from being called. An emission with no listeners reports unhandled. Notification declarations belong to the source class, while connections belong to each individual source. Supplied context remains available on repeated emissions, including context supplied as a one-use iterable; identical registrations create separate connections. Connecting to a notification the source has not declared is refused as unsupported. A listener failure is exposed to the caller.

- A listener can be disconnected by its connection identity or by its matching callback registration. Later emissions do not call the disconnected listener; removing an already absent connection has no effect.

- A connection can hold application context weakly. Such a connection does not keep that context alive, and the listener stops receiving notifications once the context no longer exists.

- Connecting or disconnecting listeners from inside a listener affects subsequent emissions, without changing the registrations receiving the current emission. A connection whose weak application context has expired receives no further call.

### FP-05: Configurable keyboard commands

- Applications can map keys to navigation, activation, menu, and redraw actions, inspect those mappings, remove mappings for an action, and restore the defaults. An independent copy can be changed without changing its source mapping. Controls use the current application key mapping to resolve actions.

- The default bindings assign arrows to directional movement, Page Up and Page Down to paging, Home and End to the corresponding extremes, Space and Enter to activation, Tab and Control-N to next selection, Shift-Tab and Control-P to previous selection, Escape to menu, and Control-L to redraw.

- Binding multiple keys to an action refuses a conflicting existing assignment without partially applying the new bindings. Explicit reassignment permits replacing the conflicting assignments.

- An unmapped key has no assigned action. Applications may also bind their own actions; assigning or removing a single key changes only that key. Restoring defaults discards custom bindings.

### FP-06: Text layout and attributed labels

- A text label accepts plain or nested attributed text and renders it at the available width. Callers can retrieve its text and associated attribute spans and replace the content. A refused content replacement preserves the previous text and attributes.

- Text alignment is left, center, or right, with left alignment by default. Wrapping can break at spaces, break at character boundaries, clip overflow, or mark clipped overflow with an ellipsis; space wrapping is the default. At widths that can hold each individual grapheme, space wrapping keeps words together when they fit on a row and splits a word longer than the available width at character boundaries. A space used as the row break is not displayed. At those widths, character wrapping fills each row with the longest prefix that fits without cutting a grapheme. Clipping retains the portion selected by alignment; ellipsis wrapping retains a prefix and marks its omitted suffix when the width can hold both retained content and the omission marker. Explicit newlines remain line boundaries, including empty lines and a final empty line after a trailing newline. Changing width recomputes the displayed rows. Centering divides spare columns between the two sides with at most one column difference.

- Tabs advance to the next configured stop measured in screen columns from the start of the displayed line. Explicit stops take precedence, followed by stops at repeating multiples of the interval from column zero. The default interval is eight columns; zero disables repeating stops, so a tab after the last explicit stop then occupies no columns. A negative interval or a nonpositive explicit stop is refused. Tabs are clipped at the line edge and provide a break opportunity for space wrapping.

- Applications can supply a custom text layout whose line placement and text-to-screen correspondence determine label rendering and cursor positioning in text editors that use that layout.

- Attributed text consists of text fragments, ordered groups of fragments, and fragments or groups with an associated attribute. Empty fragments contribute no characters. A marked fragment missing either its attribute or content, or content other than text or these groups, is refused as malformed markup. An unsupported alignment or wrapping choice is refused as invalid layout, leaving the previous layout unchanged when replacing a setting.

- Bell, carriage-return and delete characters in a Unicode or valid UTF-8 label are omitted from displayed content while remaining in the retrievable original text. Their omission does not move the following visible text or change its associated attributes.

### FP-07: Parsing and displaying captured ANSI text

- Captured text containing terminal controls can be resolved into displayable text with color, effects, hyperlinks, and DEC graphic characters. For single-column input in the default multirow mode, newline starts a new row at its first column, bare carriage return returns to the first column of the current row, and subsequent writing overwrites existing characters at the cursor while retaining any following text. Relative horizontal and vertical moves change the cursor by the requested number of positions; absolute moves select a row, column, or both, counting the first as one. Moves before the first row or column stop there. Next-line and previous-line moves also return to the first column. Omitted or zero movement counts mean one. Gaps preceding later writing are filled with blanks.

- In line-splitting mode, carriage return and newline separate results, with adjacent opposite line endings treated as one break and a trailing empty fragment preserved. Vertical cursor moves are omitted and identified as skipped operations. Direct display of one-line captured text shows its first line; conversion of a stream into line widgets retains all lines.

- Supplying captured text in successive chunks preserves incomplete controls, active attributes, character-set selection, and hyperlink state across chunk boundaries. For input that does not exhaust the padding allowance in either delivery, the final resolved content is the same as for the same complete input supplied together.

- Backspace moves the cursor without deleting text, and tabs advance to eight-column stops. Bell controls are counted, and the latest title and keyboard LED request are observable separately from the displayed text. LED states distinguish clear, scroll lock, number lock, and capitals lock. Other LED requests clear the current LED observation.

- Captured-text parsing omits and reports erase commands, scroll-region changes, cursor save and restore, mode changes, insertion and deletion commands, device queries, and tab-stop changes. Reports identify the skipped operation and its reason in encounter order. These operations do not mutate captured text as they would in an interactive terminal.

- A single forward relative cursor move is limited to 1024 positions, and an absolute row or column is limited to the 1024th position. Control-sequence parameter text of 256 or more characters and operating-system-command bodies longer than 4096 characters are skipped and reported. Reports retain the first 65,536 skipped operations per line in line-splitting mode or per complete block in multirow mode.

- Padding introduced by cursor movement is limited to 1,048,576 blank cells plus eight cells per supplied input character over a parsing session, counting each inserted empty row as eight cells. When the remaining allowance cannot fill a horizontal gap, writing occurs at the end of that row; when it cannot reach a new row, the cursor remains on the last existing row. Each curtailed placement is reported.

- Resetting text effects does not end an active hyperlink. An invalid hyperlink-opening control ends the preceding link without opening a new one. An operating-system-command string with neither a terminator nor a later escape character contributes no displayed text from its start through the end of input.

- Color and effect controls apply to subsequent text until replaced or reset, with foreground and background changed independently. Supported colors comprise the basic and bright colors, a 256-color index, and red-green-blue components from zero through 255. An out-of-range extended color is ignored without discarding later valid attributes in the same control. Effects can be set and individually removed; resetting intensity removes bold and faint together. Resetting either color restores its inheritance from the enclosing style. A full style reset restores both inherited colors and removes captured text effects. Character-set selection switches between ordinary text and DEC special graphics and remains active until changed. Two selectable character sets start as ordinary text and DEC special graphics respectively, with ordinary text selected.

- An unknown control is omitted and reported distinctly from a recognized operation that is unsupported in the selected parsing mode. In line-splitting mode, bell counts, the latest title request, and the latest LED request are reported separately for each result; absence of a title or LED request is distinguishable from a request to clear it. In multirow mode these observations cover the complete block. Empty input produces one empty result.

### FP-08: Widget decoration and size adaptation

- Horizontal padding and vertical filling position a child using left, center, or right alignment and top, middle, or bottom alignment respectively; callers can also choose a percentage between the two edges. Padding defaults to left alignment and the full available width. Filling defaults to middle alignment and the child's natural row count. Margins default to zero. Callers can choose a fixed size, the child's natural size, or a percentage of the space remaining after margins, with optional minimum sizes. A percentage chooses the same proportion of that available span, rounded to whole cells. Minimum sizes constrain relative sizing; fixed sizes take precedence over a minimum. Horizontal clipping of fixed content retains the side selected by alignment. Vertical filling crops content taller than its viewport and keeps a focused child's cursor visible when the child supplies one.

- A box child can be presented as flow content with a specified row count. Unknown alignment or size choices are refused as invalid layout configuration. Natural width can be requested from a child that reports a packed width; horizontal clipping requires a child that can render at its natural fixed size.

- Applications can add a border with an optional title, a horizontal divider with blank rows above and below, or a rectangular character fill. A border reserves one column or row for each present side, leaving its interior to the child. Its side and corner characters can be replaced; omitting a side removes its reserved column or row. A title appears in the top border, centered by default or aligned left or right, and can be replaced after creation. A nonempty title without a top border is refused as invalid decoration. A divider repeats the supplied character across one full row, with the requested blank rows above and below; its default character is a blank and its extra row counts default to zero. A character fill repeats its supplied character throughout the assigned rectangle.

- A disabled child is nonselectable, does not receive interaction through its disabling wrapper, and renders without focus. A replaceable placeholder displays and delegates interaction to its current child after replacement.

### FP-09: Responsive containers and focus navigation

- Horizontal columns and vertical piles arrange children in their supplied order. Children can request fixed space, their natural size, or a weighted share of the remaining space; unqualified children have weight one. Positive weighted shares preserve their proportions to whole-cell rounding when space permits. Column gaps default to zero and separate visible children; pile separation is supplied as child content. Columns have a default minimum width of one column. In flow sizing, columns use the largest child height and piles use the sum of child heights. In box sizing, fixed and naturally sized children reserve their requested space before the remaining space is shared. Resizing recomputes allocation while retaining the selected child when it remains present. Columns, piles, and grids initially focus their first selectable child, or their first child when none is selectable.

- A grid arranges equal-width cells left to right and then top to bottom, with caller-supplied horizontal and vertical gaps and left, center, right, or percentage row alignment. It places as many cells as fit on each row and reflows as the available width changes; if a cell is wider than the viewport, one cell occupies each row. A frame places optional flow header and footer around a box body, which has focus by default. When space is short, a focused header or footer takes priority over the other regions. When the body has focus, at least one row is reserved for it in a nonempty viewport, and the footer has priority over the header for the remaining rows.

- Container contents and focus can be inspected and changed at runtime. Nested focus can be retrieved and restored as a path through containers; a partial path changes only the named levels. A position outside a sequence container's contents or a frame region other than header, body, or footer is refused as invalid focus, leaving the previous focus unchanged. Assigning frame focus to an absent header or footer is refused; a frame initially configured to focus an absent region has no child at that region.

- A focused child receives a key before its container handles it. Unhandled left and right navigation moves between selectable columns; unhandled up and down navigation moves between selectable pile children. Grids combine movement between cells in a row and between rows. Nonselectable children are skipped, and navigation without a destination remains unhandled. Frames leave directional keys unhandled after their child declines them. Mouse interaction uses the child's displayed coordinates and can focus a selectable child at the clicked location.

- Sequential focus navigation is opt-in for columns, piles, frames, and grids, and is disabled by default. When enabled, next and previous selection follow content order, skipping nonselectable children. Entering an opted-in nested container selects its first or last selectable descendant according to the direction; a child without this option remains one stop and retains its internal focus.

- At the end of sequential navigation, a container resets to its opposite selectable edge and returns the navigation key unhandled so its parent can continue. Changes to contents or selectability affect the next navigation operation.

- When columns cannot all fit, off-screen columns are hidden while preserving the selected column when its requested width can fit. A pile whose children exceed its box height retains the focused child's visible area when that child has a weighted allocation, and clips surrounding content to the viewport. Neither layout draws outside its assigned rectangle. Fixed allocations must be nonnegative integers and weights must be finite, nonnegative numbers; declarations outside those ranges are refused as invalid layout without changing the existing contents.

### FP-10: Editable text and numeric fields

- A text editor displays a noneditable caption and editable text, with the cursor initially at the end unless a position is supplied. Typing inserts at the cursor; backward and forward deletion remove the neighboring grapheme cluster; horizontal movement steps between clusters. Home and End move to the boundaries of the displayed row holding the cursor, with End resting on that row's last position, vertical movement follows displayed rows, and mouse positioning moves the cursor to the corresponding text position.

- Single-line editing is the default. Multiline editing permits inserted newlines. Tab insertion is disabled by default; when enabled, tabs can either insert spaces or remain tab characters, with spaces as the default. Display masking conceals the edited text while preserving the actual editable value for the application.

- Text-change listeners receive the proposed new text while the previous text is still readable; post-change listeners receive the previous text after the new text is readable. Replacing text programmatically updates its rendering and value.

- Basic integer fields accept decimal digits. Extended integer fields accept digits for a caller-selected base from 2 through 36, defaulting to ten; letters represent digit values ten through 35 without regard to case. Decimal fields accept decimal digits with either a dot or comma separator, defaulting to dot. Typing an invalid digit, a second decimal separator, or a separator different from the configured one leaves the value unchanged and the key unhandled. Extended integer and decimal fields permit typed negative signs only when explicitly enabled, at the beginning and with no existing sign.

- Numeric fields expose the numeric value represented by their editable text. An empty basic integer field represents zero; an empty extended integer or decimal field represents an absent value. Extended integer string initial values must contain digits valid for the selected base, optionally preceded by a minus sign when negative input is enabled. Decimal initial values must be finite numbers or numeric text using the configured separator. Invalid initial text for these extended fields, nonfinite decimal initial values, and a decimal separator other than dot or comma are refused as invalid numeric input. Basic integer initial text and later programmatic text replacements are not character-filtered; asking for a numeric value from text that is not a number fails as invalid numeric conversion. A lone typed sign or decimal separator is likewise not yet a number.

- For a decimal initial value or decimal initial text, decimal fields preserve its decimal exponent by default: the returned value rounds the edited number to that exponent using the application's active decimal rounding rule. With an integer initial value or no initial value, the precision follows the edited text. Disabling significance preservation also returns the precision represented by the edited text.

- Basic and extended base-ten integer fields and decimal fields remove redundant leading zeros lying before the cursor after a handled edit or cursor movement. A lone zero and the zero immediately before a decimal separator remain. Extended integer fields in other bases retain leading zeros. Programmatic cursor positions before or after the editable text are clamped to its beginning or end. Left movement at the beginning, right movement at the end, vertical movement beyond the first or last editable row, backward deletion at the beginning, and forward deletion at the end leave the text unchanged and the key unhandled when no text is selected.

- Expanded tab insertion uses the next configured tab stop measured from the beginning of the current explicit line of editable text, excluding the caption and including the widths of preceding wide characters and tabs. A custom layout without tab-stop configuration uses eight-column stops for expanded tab insertion. A tab with no later stop inserts nothing. Unexpanded tabs remain one editable character.

### FP-11: Buttons and choice controls

- A button displays its label and notifies its connected listeners when activated by its activation key or primary mouse click. Keys unrelated to activation remain unhandled.

- A check box displays and exposes its checked, unchecked, or mixed state, initially unchecked. With three-state cycling enabled, activation cycles through unchecked, checked, and mixed states; otherwise activation toggles checked and unchecked, and an explicitly assigned mixed state activates to unchecked. Applications can set any of these states and replace the label; another state is refused as invalid choice state without changing the state or sending notifications.

- Radio controls in a group provide exclusive selection: selecting one deselects the previously selected member. By default the first member added is selected and subsequent members are not. Activating an already selected member leaves it selected.

- Choice-state changes notify listeners of the new state while the old state is still readable, then notify post-change listeners of the old state after the new state is readable. Assigning the existing state does not emit a change notification; programmatic changes can explicitly suppress notifications for the directly assigned control. Selecting a radio control this way can still notify a peer deselected by that selection.

- A selectable text icon renders an attributed label and shows a cursor at the configured character position only when focused and that position is visible. Its keys remain unhandled so an enclosing control can provide activation behavior.

### FP-12: Dynamic lists and hierarchical browsing

- A list view displays a vertical sequence of flow widgets within a box viewport. Moving focus, scrolling by row or page, and positioning focus within the viewport reveal the corresponding contents and keep a focused child's cursor visible. An empty list displays a blank viewport and has no focused item.

- Applications can supply list contents dynamically, with positions identified by application-defined tokens and neighbors obtained from the content provider. Built-in sequence providers refuse focus outside their contents; application-defined providers determine which position tokens they accept. Wrapping providers allow navigation between the last and first items, but a viewport displays each item at most once when a finite wrapping list is shorter than the viewport.

- In a focus-tracking mutable sequence, insertion at or before the focused item, or deletion before it, preserves that item's focus when the item remains. Deleting the focused item selects the item now at its position, or the last remaining item if that position is past the end; deleting all items removes focus.

- Flow rendering can display the full height of a finite nonwrapping list whose provider reports its length or estimated length, as well as a tree. Box rendering remains the default for list view sizing.

- A tree browser displays nodes with indentation reflecting depth and expansion indicators for parents. Nodes start expanded unless the application chooses otherwise. Expanding a parent reveals its children; collapsing it hides descendants. Visible order puts a parent before its children and follows the supplied sibling order. Navigation supports movement to parent, first child, last visible descendant, and neighboring visible nodes while retaining access to the associated application values. Right or plus expands a parent, minus collapses it, and a primary click on its indicator toggles expansion. Collapsing an ancestor programmatically does not relocate a currently focused descendant.

- Finite list views offer sequential focus navigation, disabled by default. When enabled, next and previous selection use the container navigation rules for child-first handling, selectable descendants, current contents, and returning an unhandled key after resetting at an edge. Built-in finite wrapping providers follow their supplied position order from first to last rather than cycling during the search. For other providers that repeat positions, navigation returns the key unhandled when no other selectable position is reachable before repetition.

### FP-13: Scrolling and interactive scrollbars

- A scrolling adapter presents flow or fixed content through a box viewport, initially at the top. Row commands move one row, paging moves one viewport height minus one row, and beginning and end commands move to the corresponding boundary when the child leaves those inputs unhandled. Nonnegative programmatic offsets count rows from the top; minus one selects the bottom, and each further negative step selects one row above it. Offsets are clamped to the available scroll range. A cursor outside the viewport is hidden. A child supporting neither flow nor fixed sizing is refused as incompatible content.

- A scrollbar can accompany scrollable content or a list view on the left or right, defaulting to the right with one column of width. Widths below one are raised to one; another side is refused as invalid placement. Its thumb height is the visible fraction of the content multiplied by the track height, rounded to an adjacent whole row and occupying at least one row of a nonempty track. Its position along the remaining track travel is proportional to the scroll offset within the available scroll range, rounded to an adjacent whole row; the top and bottom scroll boundaries align with the corresponding track ends. Increasing the scroll offset never moves the thumb backward. Automatic visibility is the default and shows the bar only when content overflows; forced visibility reserves its width even without overflow; hidden mode gives the content the full width while preserving scrolling.

- Clicking the scrollbar track or dragging its thumb moves the viewport to the corresponding content position, with either track end reaching the corresponding scroll boundary. With a scrollbar, including hidden mode, wheel input over the content or scrollbar moves an adapted flow or fixed child by one row per step when the child leaves that input unhandled. Optional start and end markers are shown only when the scrollbar has at least three rows and perform the same scrolling step as a wheel action toward that end when activated. A separately configured boundary style applies to a marker when its corresponding end of the content is visible. Separate normal and focus styling can be supplied for the track and thumb. Omitted focus track styling uses the normal track style, and omitted normal thumb styling uses the normal track style. Omitted focus thumb styling uses an explicitly supplied normal thumb style, otherwise the focus track style. Without a separate boundary style, markers use the track style.

- For list views, changing the focused item through scrollbar clicks and drags requires explicit permission and is disabled by default. Wheel scrolling remains available without that permission.

### FP-14: Overlays and nested pop-ups

- An overlay displays a foreground widget over a background widget using specified alignment, dimensions, and margins. The foreground obscures the covered rectangle, receives keyboard input, and supplies the visible cursor.

- A launcher can open and close a pop-up within a containing pop-up target. Without such a target, opening the launcher does not display a pop-up. Placement is relative to the launcher's visible location. Each dimension retains its requested size up to the corresponding screen dimension, and each position is constrained to the nearest position that keeps that rectangle within the screen.

- Anchored pop-ups prefer placement below the launcher when they fit there, otherwise above when they fit there, otherwise on the side with more available rows with height reduced to fit; equal available space favors below. If neither side has any available rows, placement uses the requested offset constrained to the screen rectangle.

- Pop-ups can contain further launchers. The innermost open pop-up receives keyboard input and appears relative to its own launcher. Closing it restores the outer pop-up; closing the outer pop-up removes its nested pop-ups. Entering the pop-up target preserves the open pop-up's current focus.

### FP-15: Drop-down selection

- A drop-down displays the selected label from a nonempty ordered collection of options. The first option is selected by default. Applications can inspect the options and selected index and change the selection. An empty collection, an index outside the collection, or a maximum visible item count below one is refused as invalid selection configuration; a refused selection change preserves the selection and sends no change notification.

- Within a containing pop-up target, activation or a primary mouse click opens the option list with the selected option focused and visible. The list shows at most ten items by default, or the configured positive maximum, and scrolls to reach the rest. Its anchored placement follows the available space around the control.

- Activating or clicking an option selects it and closes the list. Escape closes the list without changing selection. Changing to a different index sends a change notification carrying the new index while the previous selection remains readable; assigning the current index sends none.

- Natural width accommodates the widest option and the opening indicator, so changing selection does not change natural width. Rendering at a narrower width clips the label with an ellipsis; a label that fits is shown without one. Option attributes remain visible in the closed label and open list.

### FP-16: Progress, charts, and large lettering

- A progress indicator displays one row with distinguishable completed and incomplete portions and a percentage derived from current progress relative to the completion amount, rounded down to a whole percent. The completed region grows from the left, rounded down to whole columns without smoothing, while the percentage label is centered by default. It starts at zero out of 100 by default. Negative progress displays no completion and zero percent, progress beyond completion displays full completion and 100 percent, and a nonpositive completion amount displays no completion and zero percent. Changing progress or the completion amount updates the next rendering.

- A bar chart displays ordered bars with separately styled segments. Each supplied value is the height of a segment's top measured from the bottom, relative to a supplied positive scale maximum; values are supplied from the uppermost segment to the lowermost. A later segment occupies the lower portion of the preceding segment. Heights beyond the display range are clipped. Callers can add horizontal reference lines and scale labels at specified values. Automatic widths distribute the available columns among the bars; with a positive preferred width, bars retain that width when they fit and bars beyond the available width are omitted. Fewer than two chart attributes or a nonpositive preferred width is refused as invalid chart configuration; a refused width replacement preserves the previous width.

- With UTF-8 output and smoothing attributes enabled, progress indicators and bar charts distinguish fractional-cell completion in eighth-cell increments using partial block characters; without smoothing they render at whole-cell resolution. Progress smoothing applies only when the boundary falls on a blank label cell and never replaces a nonblank label character.

- Large lettering renders text as multirow glyphs from a chosen font, preserving the attribute of each input character across its glyph. Glyphs appear side by side in text order; their widths add and the resulting height is the font height, including for empty text. Applications can enumerate fonts, inspect each font's supported characters and glyph dimensions, and supply custom glyphs. Built-in styles comprise thin-line fonts with digit sizes three by three, four by three, and six by six columns and rows; sextant-block fonts with digit sizes three by three and two by two; and half-block fonts with digit sizes five by four, six by five, a heavy six by five variant, and seven by seven. Each supports distinct glyphs for the ten decimal digits. Digit styles use the character classes of Unicode 16.0: in a thin-line font at least half the nonblank characters of each digit are Box Drawing characters, with no Block Elements or sextants; sextant fonts use only sextants and Block Elements, with sextants appearing in at least half the decimal digits; half-block fonts use only Block Elements, with upper, lower, left, or right half blocks appearing in at least half the decimal digits. Across all ten digits at their common size, the heavy six-by-five variant covers more total cell area than the ordinary variant, measuring each block character by the fraction of its cell it fills. Characters absent from the chosen font contribute no glyph.

- Each supported 26-letter Latin case has at least thirteen distinct rendered glyphs. Supported nonspace characters render nonblank glyphs with positive width. The thin-line four-by-three and sextant three-by-three fonts support uppercase Latin letters. The half-block five-by-four, thin-line six-by-six, and half-block seven-by-seven fonts support both uppercase and lowercase Latin letters. All built-in fonts support full stop. All except the two six-by-five half-block variants support comma and percent. All except the sextant two-by-two font also support space, slash and colon. The thin-line three-by-three and four-by-three fonts additionally support exclamation, double and single quotation, number, dollar, percent, asterisk, plus, hyphen, semicolon, equals, question, square brackets, backslash, caret, underscore and grave accent. The sextant three-by-three, half-block five-by-four, thin-line six-by-six and half-block seven-by-seven fonts additionally support the remaining printable ASCII punctuation through grave accent; the last three also support opening and closing braces, vertical bar and tilde.

### FP-17: Terminal display and input

- Direct terminal display and basic terminal display draw a supplied canvas with its text, attributes, and cursor, and report the current terminal size. Starting and stopping establish and restore terminal interaction settings. Basic terminal display supports monochrome, the first eight basic foreground and background colors, and bold, faint, underline, blink, and standout effects. Direct terminal display supports all listed basic colors and effects and additionally supports 88-color, 256-color, and 24-bit modes.

- Terminal input distinguishes text characters, directional and paging keys, Home, End, Insert, Delete, Backspace, Tab, Enter, Escape, function keys F1 through F20, modified keys, and screen resize events. Mouse tracking reports button presses, releases, wheel direction, and screen coordinates. Direct terminal display can enable and disable tracking and additionally reports dragging. Basic terminal display can enable tracking; attempting to disable it after enabling is refused as unsupported. Complete character and key sequences supplied in fragments are combined while awaiting completion. When direct terminal input is integrated with an event loop, an isolated Escape becomes an Escape key after the configured completion wait rather than waiting indefinitely for another character. The completion wait defaults to 0.125 seconds and applies while available input ends in a possible prefix of a longer key sequence.

- Extended keyboard input is opt-in. On a supporting terminal it distinguishes modified keys otherwise indistinguishable in legacy input, including Control-I from Tab and Control-M from Enter. Negotiation prefers kitty keyboard reporting over xterm modified-key reporting and continues legacy input until support is confirmed. Stopping the display restores the previous reporting mode. Release-only reports do not become key presses.

- Direct terminal display emits active hyperlinks only when hyperlink output is enabled, which it is not by default. Basic terminal display shows linked text as ordinary styled text without clickable links.

### FP-18: Event scheduling and application lifecycle

- Applications can schedule a callback after a delay, cancel it before it fires, watch a readable input source, remove that watch, and receive callbacks when the event loop becomes idle. A timer fires once unless scheduled again. An explicit application-exit request ends loop execution cleanly, while an unexpected callback failure is exposed to the application.

- Applications can use the default standalone event loop or integrate with an existing event service for standard Python asynchronous tasks, reactor-based networking, desktop main-context events, asynchronous web-server events, structured asynchronous tasks, or message-socket events. The standard asynchronous, web-server, structured-task, and message-socket integrations accept asynchronous callbacks as well as ordinary callbacks. Basic terminal display does not support external event-loop integration.

- The application loop displays the current root widget, applies the input filter before dispatch, sends remaining input to the focused widget, and passes unhandled input to the application's unhandled-input handler. A filter can replace or remove events. Resize events redraw using current dimensions, and replacing the root changes subsequent display and input routing. Direct terminal display is the default.

- Application alarms can use relative delays or absolute times and carry application data. Readable-file watches and pipe notifications deliver input to registered callbacks and can be removed.

- Normal exit and failures that end application execution stop the display and restore terminal settings. Failures from directly dispatched input or readable-file callbacks are exposed to the caller. Applications can temporarily hand the terminal to other work: during the handoff the display is stopped and application input, timer, and file callbacks are not dispatched. A running application display enables mouse tracking. Returning restores the previously running display and mouse setting and redraws at current dimensions, including when the handed-off work raises an error; a display already stopped before the handoff remains stopped.

- A readable-source watch remains active until removed; registering another watch for the same source replaces its callback. Removing a watch prevents later readiness from calling it. Idle callbacks can also be removed. Application alarms and watched-input callbacks that change the displayed widgets are reflected in subsequent application drawing.

### FP-19: Embedded interactive terminal

- On supported Unix-like systems, an embedded terminal runs an actual child command or application-supplied callable. Executed commands use inherited or supplied environment settings and are told to use the Linux console terminal type; application-supplied callables inherit the parent's environment. With no command supplied it starts the user's shell with the same environment handling as an executed command. Child output appears inside the widget, keyboard input reaches the child, and widget resizing updates the child's terminal dimensions.

- Child text attributes, DEC graphics, and UTF-8 characters appear in the embedded screen.

- Applications can capture input for the child or release it to surrounding widgets. The default escape key is Control-A. Scrollback permits viewing earlier output while retaining the active terminal contents. Child requests for a title change, bell, or keyboard LED state are delivered as distinct notifications.

- Selecting a mouse tracking mode replaces the previous tracking choice; disabling a tracking mode turns tracking off. When requested by the child, mouse reporting sends mouse events to the child and bracketed paste distinguishes pasted content from ordinary keystrokes. Extended kitty keyboard mode can be set, saved, restored, and queried independently for the main and alternate screens. Disambiguation or all-key reporting preserves Shift, Control, Alt, Super, and Hyper modifiers on delivered key presses; alternate-key reporting includes the shifted form, and associated-text reporting includes the text the key types. The child receives presses only, even if it requests event types. Pasted content remains text. Without extended reporting, a key with no supported legacy representation is returned unhandled.

- Child termination is observable, and closing the embedded terminal terminates a remaining child that the application is permitted to signal and releases its terminal resources.

- The embedded screen initially overwrites at the cursor, wraps at the right edge, and shows its cursor. Cursor motion is clamped to the screen, or to the active scrolling region in region-relative mode. Carriage return moves to the first column; line feed moves down without changing column unless newline mode is enabled. Backspace moves left without deletion. At the bottom of the scrolling region, line feed shifts that region upward and adds a blank bottom row; reverse line feed at its top shifts it downward and adds a blank top row. Rows outside the region remain unchanged.

- Line and screen erasure can clear from the cursor through the end, from the beginning through the cursor, or the whole line or screen, leaving the cursor in place. Character insertion shifts later characters right and drops overflow; deletion shifts later characters left and fills the vacated end with blanks. Line insertion and deletion shift only rows from the cursor through the end of the scrolling region, adding blank rows and dropping displaced rows. Erased and newly inserted blank cells carry no hyperlink.

- Tab stops initially occur every eight columns. The child can set a stop at the cursor, clear that stop, or clear all stops; tab advances to the next stop or the last column. Cursor save and restore have a position-only form and a form that also preserves the saved text attributes and character-set selection. Disabling wrapping makes further writing overwrite the final column; enabling insert mode shifts existing characters for each written character.

- Main-screen scrollback retains the most recent 10,000 removed rows. The alternate screen does not add scrollback. Browsing scrollback is clamped to the retained rows, and returning to the live screen restores its current contents. While child input capture is released, Page Up and Page Down browse by half the viewport height, rounded down. A rendered embedded terminal starts with child input released. The escape key releases captured input; pressing it twice sends that key to the child and resumes capture. While capture is released, a key bound in the application's key mapping remains available to the enclosing application, and any other key is sent to the child and resumes capture.

- Basic alternate-screen switching retains the contents of both screens. The clear-on-return variant clears the alternate screen when leaving it. The save-and-clear variant saves the main cursor, clears the alternate screen on entry, and restores the main cursor on return. Resizing narrows rows by clipping their right edge and widens them with blanks; shrinking height moves top main-screen rows into scrollback and growing height restores retained rows before adding blank rows. It does not rewrap existing rows.

### FP-20: HTML, web, and LCD displays

- HTML screenshot output renders a supplied screen as selectable text with its foreground, background, and visible cursor. Text containing HTML-significant characters is displayed literally. Applications can supply successive screen sizes and input-event batches, consumed in order by size queries and input reads. Exhausting the supplied input ends the application loop normally. Collecting screen fragments returns drawings in drawing order and clears the collected record.

- On Unix-like systems, the experimental web display delivers screen updates to its browser client and accepts keyboard input and resize requests. A valid resize request supplies nonnegative decimal column and row counts and updates the screen dimensions, capped at 200 columns and 100 rows. A malformed resize line does not change dimensions and remains ordinary input. Text input is decoded using the request's declared character encoding; an unknown encoding or text invalid in that encoding is refused as malformed input rather than delivered to the application.

- HTML screenshots and web output make links clickable only for HTTP, HTTPS, mailto, SFTP, and file destinations. Other destinations retain their displayed text without becoming clickable links.

- With a connected Crystal Fontz 635 display, LCD output draws text and cursor on its 20-column, four-row character screen and turns its six buttons into up, down, left, right, enter, and exit input. Color and hyperlinks do not alter the LCD's character display. Drawing observes device flow control: a further drawing command is withheld until the preceding command is acknowledged.
