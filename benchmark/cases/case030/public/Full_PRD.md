# Zelvori — Full Product Requirements

Zelvori translates typed Python scientific programs into native programs, Python extension modules, and executable Python source.

### FP-01: Typed source validation

- Accept source with annotated function arguments and infer the types of local values and ordinary function results from their expressions. Accept explicit local and result annotations, string annotations, and aliases for fully specified types. Recursive functions require a declared result type; missing required type information is refused as an incomplete type declaration. Private functions explicitly permitting omitted argument types may omit argument annotations when their calls determine the argument types.

- Support Boolean, integer, real, complex, and string scalar values. Numerical declarations include signed integers of 8, 16, 32, and 64 bits, real numbers of 32 and 64 bits, and complex numbers with 32-bit or 64-bit real and imaginary components. Unqualified real values use 64-bit precision, unqualified complex values use two 64-bit components, and unqualified integers use the native integer width reported by the host numerical array library. String support covers literal values, assignment, equality, inequality, passing, returning, and printing; Fortran additionally supports concatenation.

- Refuse reassignment that changes a variable's established numerical type or array rank, including conflicting types assigned by alternative branches. Refuse reassignment of a scalar declared constant and whole-slice augmented updates to an array argument declared read-only, identifying the incompatible assignment. Refusal of ordinary scalar-index writes to a read-only array is not covered.

- Type validation accepts valid typed source without producing a runnable artifact and reports unresolved names, unresolved imports, missing required annotations, and incompatible argument types as source errors. Malformed syntax is rejected during syntax or type validation. Invalid source diagnostics identify the affected source and distinguish malformed syntax from incompatible or unresolved program meaning; an affected line is identified for incompatible assignments, unresolved names, incompatible calls, and missing argument annotations, but need not be present for other missing declarations or unresolved imports. Successful standalone syntax-only validation is not covered.

### FP-02: Scalar computation and control flow

- Translate scalar addition, subtraction, multiplication, true division, floor division, remainder, powers, unary signs, comparisons, Boolean operations, and integer bit operations according to the Python 3.10 Language Reference, using the supplied operands, operand types, expression grouping, and evaluation order. Integer results are exact when intermediate values fit the declared integer range; division and remainder support requires nonzero divisors, and shifts require nonnegative shift counts within the integer width.

- Preserve assignment, simultaneous unpacking, augmented assignment, conditional expressions, branches, counted loops, conditional loops, nested loops, loop termination, iteration skipping, and early return according to the Python 3.10 Language Reference for the submitted program and arguments. Counted iteration supports integer ranges with a nonzero step. Augmented assignment covers addition, subtraction, multiplication, true division, floor division, remainder, bitwise conjunction and disjunction, and left and right shifts.

- Preserve scalar conversions among Boolean, integer, real, and complex values, numerical absolute value, rounding, and scalar type tests according to the Python 3.10 Library Reference for the supplied values. Printing exposes the values in the program's order and honors caller-selected separation and line termination.

- For finite scalar arithmetic with representable intermediate results, preserve the numerical value of the corresponding Python computation. For an individual operation on 64-bit real components, the absolute difference from Python evaluation must not exceed 0.00000000000001 plus 0.0000000000001 times the magnitude of that computation's result; for 32-bit real components the bounds are 0.000001 and 0.00001 respectively. Apply the same bounds separately to each complex component. These bounds cover individual operations, not an arbitrary length of accumulated computation.

- In a native script built with debug compilation enabled, an assertion with a true condition permits execution to continue; a false condition terminates execution unsuccessfully and prevents subsequent statements from executing. An explicit program exit terminates execution immediately: an omitted status or zero indicates success, a nonzero integer indicates failure, and a text reason indicates failure and exposes the supplied reason.

### FP-03: Compiler configuration

- Provide compiler configurations for GNU, Intel, NVIDIA, and LLVM, with GNU as the default family. A caller can instead supply a custom compiler configuration or select a registered family. An explicit compiler selection overrides the environment-selected default; a selected configuration determines the native compiler, compilation options, include locations, and linked libraries used for the build.

- Export a selected compiler configuration for reuse, with a distinct configuration for each built-in family, and validate a supplied configuration. Reject malformed configuration documents, target languages other than C, C++, and Fortran, recognized settings supplied with an incorrect outer value type, and configured include, library, or dependency paths that are relative or do not exist. A library may instead be specified by its link name. An unrecognized setting or an omitted language setting produces an advisory rather than, by itself, causing validation to fail; each advisory identifies the affected setting and language. A complete configuration containing only recognized settings produces no advisories. Configuration checking covers language-to-settings mappings with text-valued executable descriptions and lists of text-valued build options and paths; malformed nested structures and mixed-type list elements are not covered.

- Register a valid compiler configuration under a caller-selected name, using an available native toolchain and an absolute registration-directory location, so that later invocations can select it, and remove an existing registration on request. Reject an already registered name without replacing its registration, removal of a nonexistent registration, and a name that resolves outside the configured registration directory without creating that registration. Removing a registration makes it unavailable for subsequent selection.

### FP-04: Native translation and artifact delivery

- Given typed Python source and an available native toolchain, produce C or Fortran source and a loadable Python extension module. Source containing a script entry block also produces a runnable native executable whose execution performs that block. Fortran is the default translation target.

- A translation-only request delivers target-language source without building a runnable native artifact. The selectable translation targets are Fortran, C, C++, and Python. C++ support is preliminary and is limited here to translation of modules containing scalar declarations; the C and Fortran behavioral requirements do not extend to arbitrary C++ programs.

- Honor a caller-selected output destination, native compilation options, wrapper compilation options, include directories, library directories, and linked libraries. A build requiring an unavailable compiler or library fails as an unsuccessful native build; it does not return a usable newly built extension or executable.

- Refuse a nonexistent source file, an input that is not a Python source file, and an unrecognized target selection as invalid invocation inputs. Debug compilation is disabled by default, can be selected through the environment, and is overridden by an explicit caller choice.

- Type-only validation takes precedence over translation-only delivery and delivers neither target-language source nor a runnable artifact. Malformed syntax remains rejected when validation modes are combined. Successful syntax-only validation and its precedence over other modes are not covered.

### FP-05: Callable Python integration

- In a running Python session, accept a source-backed function, a module containing functions, or source text and return the translated callable or module for use in that session. Enclosing scalar constants, numerical-library imports, and type aliases can supply context for an individual function; an unresolved external object is refused as an unresolved dependency. Each request delivers the translation of the source it supplies, also when an earlier request used the same output location and names. Previously delivered callables retain their original computation. For a C or Fortran target, translation pays off in speed: for a scalar computation dominated by an integer loop of about two hundred thousand iterations, the best of several calls to the translated callable takes at most one third of the time of the best of several calls to the submitted Python function with the same arguments in the same session.

- Preserve positional arguments, named arguments, positional-only restrictions, keyword-only parameters with declared defaults, declared defaults for other parameters, optional arguments, calls between translated functions, and recursive calls with declared result types. Required keyword-only parameters are not covered for native wrappers. Argument binding follows the Python 3.10 Language Reference for the declared signature and supplied arguments. Missing required arguments, duplicate values, unexpected named arguments, and incompatible argument types are refused as invalid calls.

- Return scalar results, multiple results in their declared order, and no-result completion as expressed by the source. Functions marked private remain callable within their defining translated module but are unavailable for public Python import.

- Within translated code, accept typed functions as arguments and as declared default arguments. Calling such an argument invokes the supplied function with the submitted values and returns its computed result; Fortran refuses functions whose argument or result declarations are incompatible with the declared callable type. C callers must supply compatible callable argument and result declarations.

- Accept locally assigned anonymous functions whose arguments are determined by their calls. Calling one evaluates its declared expression with the supplied argument values according to the Python 3.10 Language Reference. Passing these anonymous functions as callable arguments is not covered.

### FP-06: Numerical arrays and shared views

- Accept numerical arrays with declared element type, rank, and C or Fortran ordering, and preserve their shape, element values, and caller-visible mutations. Array declarations without an explicit multidimensional order use C ordering. Refuse Python calls whose arrays have an incompatible element type, rank, or required dimensional ordering as incompatible array arguments. Refusal solely for a stride gap in an otherwise compatible ordering is not covered.

- Support basic integer indexing and slicing with positive steps, omitted slice bounds, and literal negative indices, following the NumPy 2.1 Reference for the supplied array, indices, bounds, and steps. An explicit negative-index opt-in additionally enables negative indices computed at run time. General negative-step slicing is outside the C support.

- A slice assigned to another local variable shares data with its source: writes through it change the corresponding elements of its source, and writes to those source elements remain visible through the view. A requested array copy has independent data. Refuse replacement of an owning array with a view onto another array, or replacement of its allocation while another local variable still views its data.

- Return newly created arrays and multiple array results to Python with their computed values, dimensions, element types, and declared ordering intact. A returned owning array remains usable after the translated call has finished. Returning noncontiguous views to Python is not covered.

- Expose array dimensions, total element count, element type, real and imaginary components, complex conjugation, and transposition by reversing axes, according to the NumPy 2.1 Reference for the supplied array. Transposition preserves the association between corresponding elements and shared data; specifying an arbitrary axis permutation is not covered.

### FP-07: Generic and elementwise functions

- A function declared with independent unions accepts all combinations of the declared argument alternatives. Arguments sharing one constrained type variable must use the same selected alternative. Alternatives can distinguish numerical scalar kinds and precisions, array ranks, and array element types. Constrained type declarations supplied by the enclosing Python context are accepted for interactive translation. Each accepted call computes the declared function body for those types; a call matching no declared combination is refused as an incompatible call.

- Type tests and optional-value tests inside a generic function select the behavior corresponding to the supplied type or absent value. Code applicable only to a different declared alternative does not make an otherwise valid alternative fail.

- A scalar function with one argument declared elementwise can be called from translated code on a numerical array. Its result has the input shape, and each result element equals the scalar function evaluated on the corresponding input element.

### FP-08: Typed containers

- Support local homogeneous and heterogeneous tuples, tuple construction, concatenation, repetition, unpacking, length, and indexing according to the Python 3.10 Language and Library References for the supplied elements and operations. Homogeneous scalar tuples can be passed from Python with variable length; heterogeneous tuple selection requires a constant integer index and is refused when the selected element cannot be determined from the source. Returning a homogeneous tuple is supported for Fortran; that return form is not covered for C.

- Support homogeneous numerical lists with construction, indexed reads and writes, membership, equality, length, appending, insertion, extension, removal by position, clearing, reversing, repetition, and slice assignment. Values and element order follow the Python 3.10 Library Reference for the supplied list and operations. Removal by position requires a valid position in a nonempty list. Read-only numerical list arguments are accepted from Python, and returned lists expose the resulting elements to Python.

- For C, support lists containing homogeneous lists, preserve shared references to nested lists across indexing and removal, and reflect mutations of list arguments in the calling Python list.

- Support homogeneous numerical sets with construction, membership, length, insertion, removal of an existing element, discard, arbitrary-element removal from a nonempty set, clearing, copying, union, intersection, difference, disjointness, and their updating forms. Read-only set arguments are accepted from Python, and returned sets expose their resulting elements. C also reflects mutations of set arguments in the calling Python set. Membership and resulting elements follow the Python 3.10 Library Reference for the supplied sets and operations.

- Support dictionaries with homogeneous numerical keys and homogeneous numerical values, including typed empty construction, membership, length, lookup of an existing key, indexed updates of existing keys, removal of an existing key, removal with a supplied default, removal of an arbitrary pair from a nonempty dictionary, clearing, and iteration over keys, values, or pairs. Dictionary operations follow the Python 3.10 Library Reference for the supplied entries, except that iteration and arbitrary-pair removal have no insertion-order guarantee. Returned dictionaries expose the resulting key-value associations to Python. C additionally supports string-key construction, existing-key updates, returned associations, and lookup with a supplied default. Inserting absent keys through indexed assignment, direct membership tests on C string-key dictionaries, dictionary arguments, and dictionary class attributes are not covered.

- Construct homogeneous list comprehensions over finite integer ranges and numerical sequences, and evaluate sums of generator expressions, including nested iteration, according to the Python 3.10 Language and Library References for the submitted element expression and iterable order. Numerical extrema over scalar arguments are supported, with C support limited to two arguments; Fortran also supports extrema of generator expressions.

- Iteration over numerical arrays, tuples, and lists supports enumeration, paired iteration, mapped iteration, and Cartesian products according to the Python 3.10 Language and Library References for the supplied iterable values and function. Paired iteration requires at least two inputs and either that every input length is fixed by the source or that no input length is fixed by the source. Direct set iteration and Cartesian products of sets are supported without an iteration-order guarantee.

### FP-09: User-defined objects

- Accept a source-backed class for interactive translation, or a class defined in a submitted module, and expose the translated class to Python. Translate classes with typed initialization arguments, scalar or array instance attributes, instance methods, and read-only properties. Creating an instance initializes its attributes as specified by the source; method calls and property reads expose its current state. Instance attributes can also be initialized in a method. Assignment to a read-only property is refused as a forbidden attribute update and leaves the instance state unchanged.

- Allow translated instances to be passed to and returned from translated functions and methods. Changes through an instance reference remain observable through other references to that instance. Array attributes that refer to an input array retain shared mutations with that input array.

- Honor user-defined addition, subtraction, multiplication, division, left and right shifts, bitwise conjunction and disjunction, their in-place forms, and length. Element lookup supports Python-side indexing and explicit lookup-method calls within translated code. Direct, reflected, and in-place power behaviors support explicit power-method calls within translated code; power operator syntax in translated code and through Python calls is not covered. The operation invokes the behavior defined by the class and exposes its result or updated state. Reflected arithmetic and membership behavior are supported inside translated code, without requiring corresponding Python-callable reflected operations.

- Class initialization arguments must each have one type; union alternatives and constrained type variables for these arguments are refused as unsupported initialization declarations. Inheritance and static class data are outside this class capability.

### FP-10: Scalar mathematical libraries

- Translate real-valued square root, absolute value, exponential, natural and base-ten logarithms, sine, cosine, tangent, inverse sine, inverse cosine, and inverse tangent, two-argument arctangent, hyperbolic sine, cosine, and tangent and their inverses, floor, ceiling, truncation, sign copying, two-dimensional Euclidean distance, the error function and its complement, gamma, and logarithm of the absolute gamma value. Results follow the Python 3.10 Library Reference for the supplied mathematical operation and operands on finite inputs within the operation's real domain, excluding poles and overflow. C additionally supports the base-two logarithm, the logarithm of one plus the supplied value, exponential minus one, multiplication by a power of two, and the floating-point remainder based on the nearest integer quotient with ties to even.

- Translate complex square root, exponential, sine, cosine, tangent, inverse sine, inverse cosine, and inverse tangent, hyperbolic sine, cosine, and tangent and their inverses, phase, polar decomposition, and reconstruction from magnitude and phase. Results follow the Python 3.10 Library Reference for the supplied complex operands, or supplied magnitude and phase, away from branch cuts, singularities, and overflow.

- Mathematical constants for the circle ratio, the base of natural logarithms, and a full turn are available in translated numerical expressions. Integer factorial for nonnegative arguments, and greatest common divisor and least common multiple for signed integer arguments, preserve the Python 3.10 Library Reference result when results fit the declared range. Least common multiple excludes simultaneous zero operands. Conversion between degrees and radians follows the same reference for the supplied angle.

- For these individual mathematical evaluations with 64-bit real components and finite reference results, absolute numerical error is at most 0.00000000000001 plus 0.0000000000001 times the magnitude of the reference result, measured separately on real and imaginary components. C supports finite-value, infinity, and not-a-number classification for real inputs; Fortran supports not-a-number classification. Complex special-value classification is not covered.

### FP-11: Numerical array computation

- Create arrays from homogeneous numerical sequences, shapes, constant fills, existing-array shape and type, arithmetic ranges, and evenly spaced intervals. Shape, contents, element type, and requested C or Fortran ordering follow the NumPy 2.1 Reference for the supplied data, shape, bounds, step, fill, type, and ordering. Uninitialized creation promises shape and type only. Shape-based zero, one, and uninitialized creation defaults to 64-bit real elements and C ordering. Creation from an existing array defaults to its element type, shape, and ordering; explicit type, shape, and ordering overrides take precedence. Copying without an ordering override preserves the source ordering. Creation from sequences infers the element type from the elements and defaults to C ordering; constant fills infer the element type from the fill value. Arithmetic ranges default to a zero start and unit step, exclude the stop, and infer their element type from the supplied bounds and step. Evenly spaced intervals default to 50 samples and include the final endpoint unless the caller excludes it; this capability supports sample counts of at least two. Their inferred element type follows the supplied bounds but is real rather than integer when both bounds are integers.

- Compute elementwise addition, subtraction, multiplication, division, powers, remainder, comparisons, absolute value, square root, exponential, exponential minus one, natural logarithm, sine, cosine, tangent, inverse sine, inverse cosine, and inverse tangent, two-argument arctangent, hyperbolic sine, cosine, and tangent and their inverses, floor, sign, and real special-value classification. Broadcasting and results follow the NumPy 2.1 Reference for the supplied operands, types, and shapes. Arithmetic support requires compatible shapes and values in the operation's domain, with finite representable intermediates. Comparisons accept scalar operands or array operands of matching rank and element type; array equality and inequality are supported only for C.

- Compute sums, minima, and maxima over an entire array or a specified constant axis or tuple of distinct constant axes. A constant choice controls whether reduced dimensions are retained; by default they are removed and all elements are reduced. Callers may supply an initial value and a result array of matching shape and type; the operation writes the reduction into that array and returns a reference to it. A sum additionally accepts a requested accumulation type and otherwise uses the NumPy 2.1 default type promotion. Values and shapes follow the NumPy 2.1 Reference for the supplied array, operation, axes, initial value, requested type, and dimension-retention choice. Minima and maxima require a nonempty reduction when no initial value is supplied. C reductions retaining dimensions cover a single axis or adjacent axes; nonadjacent multi-axis reductions retaining dimensions are outside C support. Compute vector norms along a single constant axis or over all entries, with optional retained dimensions, according to the same reference for the supplied array and norm order. A vector norm accepts a nonnegative literal real order or positive-infinite order. C additionally supports finite negative orders. Negative-infinite literal orders are not covered. The default is the Euclidean norm of all entries. Nondefault matrix norms and multiple-axis norm requests are not covered. Product over all elements is additionally supported for Fortran.

- Compute vector inner products, matrix multiplication, batched matrix multiplication with matching batch dimensions or a shared lower-rank matrix, three-component cross products, and conjugating vector dot products. Results follow the NumPy 2.1 Reference for the supplied ordered operands, element types, component-axis choices, and compatible dimensions. Matrix multiplication accepts vectors and arrays with matrix trailing dimensions, not scalar operands. Dot products can write to a caller-provided result array.

- Conditional array selection chooses from two supplied values according to each element of a Boolean condition, with NumPy 2.1 broadcasting for matching shapes or a shared vector combined with a scalar candidate. Expansion of singleton dimensions within ranked candidates is not covered. Fortran additionally provides counts of nonzero entries over all elements or a selected axis, optional retained dimensions, and the positions of nonzero entries in a one-dimensional array, following the NumPy 2.1 Reference for the supplied array, axis, and dimension-retention choice. Counts default to all elements with reduced dimensions removed.

- For Fortran, generate uniform real random values between zero inclusive and one exclusive, and uniform integers between a supplied lower bound inclusive and upper bound exclusive. Successive generated values, within one array and across calls, are independent draws from that distribution. With only one integer bound, the lower bound is zero. Real generation produces 64-bit real values. Support scalar results and arrays with caller-specified positive dimensions; integer generation also accepts a declared integer precision and requires the lower bound to be less than the upper bound, with both bounds representable at that precision. Random array creation is assigned to a variable before further array arithmetic uses it.

- For individual elementwise operations on finite inputs without overflow, return exact discrete results and numerical array results within an absolute difference of 0.00000000000001 plus 0.0000000000001 times the magnitude of the NumPy 2.1 result for 64-bit real components. For 32-bit real components, the corresponding bounds are 0.000001 and 0.00001. Measure every output element and each complex component separately, using the same input values, data types, and requested operation. Integer reductions are exact when all intermediate and final values fit the result type. For floating sums and dot products, compare each component with the exact sum of the supplied terms: the absolute error must not exceed 0.00000000000001 plus 0.0000000000001 times the number of terms times the sum of their absolute magnitudes for 64-bit components; the corresponding 32-bit bounds are 0.000001 and 0.00001. These bounds apply when the terms and intermediate results are finite and representable. For vector norms of real or complex arrays with finite nonzero order, the default Euclidean norm, and Fortran real or complex floating products, compare each final result component with the exact mathematical result for the supplied values and operation. For 64-bit components the absolute error is at most 0.00000000000001 plus 0.0000000000001 times the number of reduced entries times the greater of one and the magnitude of that result; the corresponding 32-bit bounds are 0.000001 and 0.00001. This composite guarantee covers nonempty reductions with finite representable magnitude powers, partial sums or products, and final results; negative norm orders require nonzero entries. Zero-order norms and real infinite-order norms remain exact. Complex positive-infinite-order norms use the same component error guarantee as finite-order norms.

- Determine a common numerical result type from supplied scalar values, arrays, and numerical type declarations according to the NumPy 2.1 Reference type-promotion rules.

### FP-12: Existing native library interoperability

- Given an existing C or Fortran library and a typed interface description matching its declarations, produce a Python-callable extension that invokes the supplied library. Scalar arguments, scalar results, multiple results, and argument updates retain their declared meanings. Missing link dependencies prevent successful delivery of the extension.

- Let an interface map Python-facing functions, classes, and methods to differently named native declarations, and expose overloads selected by declared argument types. Expose native object creation, instance methods, readable attributes, read-only properties, and defined operator behavior to Python. Calls matching no declared overload are refused as incompatible calls. Readable native Fortran attribute names that collide with reserved names or intrinsic names are not covered.

- Translate Python programs that import these described libraries so that their resulting native programs use the supplied library and retain its results and mutations. Fortran interfaces also accept numerical array arguments with matching element precision, rank, and ordering. Native declarations and interface descriptions must agree; arbitrary mismatched native declarations and ownership-ambiguous array returns are not covered.

### FP-13: Modules and multi-file projects

- Translate cooperating Python modules with absolute imports, relative imports, renamed imports, and imported functions, constants, and classes. A program's imports select the same definitions, and module initialization establishes the values used by subsequent calls. Repeated imports do not repeat the module's initialization side effects. Fortran renamed imports cover functions and modules; imported constants retain their original names.

- Build a selected collection of project files into usable extension modules and script executables. Selection can come from an explicit file list, file patterns, or a file containing the list. A separate output destination receives the project's generated deliverables.

- Reject a project whose directory-level import dependencies form a cycle as a circular dependency, identifying the participating directories and distinguishing this from a missing imported source. A project with an unresolved imported module fails as an unresolved dependency, identifying the imported module and the source that imports it.

### FP-14: Symbolic expression evaluation

- Accept a symbolic numerical expression and an ordered association of its input symbols with types, and return a compiled callable that evaluates the expression for arguments in that order. Cover real scalar and numerical array expressions composed of arithmetic and the mathematical operations described here; array expressions retain their elementwise meaning and result shape. A declared result type is supported when compatible with the expression's inferred numerical type; implicit conversion to an incompatible type or precision is not covered.

- An explicit output-array request writes the expression's values into the caller's supplied array. The default returns a result. Output-array evaluation requires an array result declaration and caller storage matching its shape and element type. Refuse an output-array request without a declared result type, an input association that does not map symbols to type descriptions, or a result type description of the wrong kind as an invalid expression-compilation request.

### FP-15: OpenMP host computation

- With an OpenMP-capable C or Fortran toolchain, translate caller-specified host parallel regions, work-sharing loops, reductions, private and shared values, single-execution regions, critical regions, barriers, atomic updates, tasks with waits, and sections. The values, updates, and synchronization observable from a race-free submitted program follow OpenMP 5.1 for that program's directives, clauses, shared inputs, initial private values, and available host execution resources. For C, a reduction variable is exposed through a single scalar return or caller-owned storage; returning that variable as one component of multiple scalar results is not covered.

- Calls that select or query host team size, identify the calling thread, inspect nested team ancestry, or query whether execution is in a parallel region obey OpenMP 5.1 for the submitted program, its runtime configuration, and the active host region. User declarations of private data distinguish per-participant values from shared values in the computation's results. Variables without a predetermined OpenMP data-sharing attribute are shared by default unless explicitly declared otherwise; the OpenMP rules for loop iteration variables take precedence.

- Preserve host loop results for combined parallel-loop, standalone vectorized-loop, and combined parallel-loop-with-vectorization directives. Standalone work-sharing loops combined with vectorization are outside Fortran support. Device offloading and arithmetic expressions inside directive clauses are not covered; the presence of a target-device directive does not establish a GPU execution capability.

### FP-16: Collective interactive compilation

- Accept an MPI communicator for an interactive compilation requested collectively by its participating processes. With a shared accessible build location and native toolchain, by default every participant receives a usable translated function or module and can independently call it on that participant's data.

- A caller-selected root process supplies the compilation source; other participating processes need not supply the same source object. The default root is process zero. A caller can instead request delivery only to the root; the other participants then receive no translated object. This capability supports successful collective compilation; collective delivery of compilation failures and translation of Python MPI message-passing operations are outside its scope.

### FP-17: Python target output

- An explicit Python target request delivers executable Python source or a callable Python object for a submitted typed program within the capabilities defined here. Its scalar, control-flow, call, array, and container behavior remains that of the submitted Python computation. This target produces no native extension or native executable.

- Python target output retains imports and accepts product-specific acceleration annotations without requiring native execution support. Source type errors still fail validation. Native-only OpenMP runtime operations are outside this target's executable coverage.

### FP-18: Generated artifact cleanup

- On request, remove product build directories and saved translation artifacts from selected directories. The default selection is the current directory, and traversal is recursive by default. A nonrecursive request leaves descendant-directory artifacts untouched. Files and directories outside the selected artifact categories and traversal scope retain their contents and permissions.

- Optional extension cleanup additionally removes Python extension libraries in the selected scope, and optional program cleanup additionally removes files marked executable in that scope. These options are disabled by default; program cleanup is based on executable status and does not guarantee that only product-created programs are removed. Nonrecursive program cleanup is covered only for selected directories without ordinary descendant directories; nonrecursive default and extension cleanup retain their descendant-preservation guarantee.
