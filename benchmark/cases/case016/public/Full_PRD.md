# prosecheck — Full Product Requirements Document

## Product overview

**prosecheck** is a local detector for AI-writing patterns. It is a command-line tool and an agent plugin. There is no website and no hosted version. Nothing the user writes is uploaded; there is no account; no text leaves the machine. Any site offering a service under this name is unrelated to this project.

A first-time user installs the prosecheck plugin into a coding agent (Claude Code, or another agent via the portable contract), restarts, and runs `/prosecheck doctor`. When the install is sound and the tool is on, the doctor answers with four successful-check lines. From then on, two layers work together. A writing contract is placed in the session (and into any subagent) so prose deliverables are shaped as they are written. After a supported file-edit tool saves a prose file, a saved-file guard scores the first 262,144 characters of extracted prose against a catalogue of 71 documented patterns and, when the score is above the active threshold, names the flagged spans and asks for them to be fixed. The same detector can be run by hand on a file path or on standard input. Python standard library only, no network, no model. Prose only, never code.

This document specifies **user- and integrator-observable behavior only**. Exact published symbol names, import paths, and call spellings belong in the Interface Contract, not here. Every feature point below corresponds to behavior that exists in the finished prosecheck product (version 0.9.3). Feature points are ordered so foundational capabilities come first; a later feature point may refine an earlier one only when it says so explicitly.

## Terminology

| Term | Meaning in this PRD |
| --- | --- |
| **prosecheck** | The product: a local prose-pattern detector and the agent plugin that wraps it. |
| **Detector** | The command-line scanner. Given a file or standard input, it either prints a structured report (score, band, pattern findings) or, with the cleanup switch, prints scrubbed text. |
| **Catalogue** | The 71 documented AI-writing patterns, numbered 1–71, with Before/After examples in the pattern catalogue. A pattern describes prose, never a writer. |
| **Machine-checked pattern** | One of the 62 catalogue numbers that the detector can report on a scan. The other 9 numbers have no detector and are worked only by reading during a rewrite. |
| **Score-moving pattern** | One of the 50 machine-checked catalogue numbers that can change the 0–100 score. The remaining 12 machine-checked numbers are **writing advice**: when they appear in the report they count for nothing. |
| **Score** | An integer from 0 through 100 inclusive. It is a triage heuristic on the writing in front of the detector, not a calibrated authorship classifier. |
| **Band** | One of five named ranges of the score: `clean`, `light tells`, `mixed`, `heavy tells`, `pervasive tells`. Every band describes the prose; none of them names an author. |
| **Hook phrase** | The plain-language rendering of a band used by the plugin: `reads clean`, `reads mostly clean`, `reads with some AI tells`, `reads with heavy AI tells`, `reads with pervasive AI tells`. |
| **Confidence** | How much the score is worth, reported as `none`, `low`, `moderate`, or `high` from word count and how many distinct score-moving families fired. |
| **Writing contract** | The always-on prose rules injected into a session, a prompt, and a subagent. It governs prose deliverables only. It never touches source code, comments, commits, configuration, or the chat register. |
| **Saved-file guard** | The plugin layer that, after a supported file-edit tool writes a prose file, scores that file and, when flagged, returns a nudge naming the file, the hook phrase, the score, the band, and the fired pattern labels. |
| **Level / mode** | The one-word operating level stored for the install: `lite`, `full`, `strict`, or `off`. Default is `full`. |
| **Prose file** | A saved file whose extension is in the twenty-format set (FP-02). |
| **Extracted prose** | The visible text the detector actually scores: the file body for plain text; the document text pulled out of a supported archive or notebook. |
| **Scan window** | The first 262,144 characters of extracted prose. Everything past that window is unread. Character-layer rules use the same window. |
| **Character cleanup** | The detector’s cleanup switch: strip invisible and zero-width codepoints that carry no meaning where they sit, normalize non-standard spaces to ordinary space (U+0020) where they are not load-bearing, fold mixed-script lookalikes inside Latin runs to ASCII, and trim stray whitespace. Visible text is left alone. |
| **Session ledger** | A per-session record of what the guard scored or skipped. It holds each file’s base name, score, band, and up to five pattern labels — never the document text and never the full path. |
| **Host agent** | The coding agent that loads the plugin (Claude Code and, via `/prosecheck init`, other agents that read `AGENTS.md` or a Cursor rule). |

## Public surface inventory

prosecheck is a **command-line detector** with a companion **agent plugin**. The detector needs Python 3.9 or newer and nothing else. The plugin’s saved-file and command hooks need Node.js. There is no installable package, no compiled extension, and no runtime third-party dependency.

The public surfaces, grouped by feature point, are:

- The detector command: a file path or standard input in, a structured report or scrubbed text out; optional cleanup and resampled-interval switches; help (FP-01, FP-03).
- Extraction of visible prose from the twenty supported formats, with the 512 KB / 4 MB size caps and the 262,144-character scan window (FP-02).
- The writing contract, placed at session start, on the prompt, and inside a subagent, including the one-time first-run welcome (FP-04).
- The saved-file guard on Write, Edit, MultiEdit, NotebookEdit, and apply_patch, including Codex apply_patch payloads (FP-05).
- The `/prosecheck` command (and the namespaced form `/prosecheck:prosecheck`): levels, status, show, check, doctor, stats, init, help (FP-06).

Feature points below group these entries by capability. They do not invent additional product surfaces.

The bundled skill file instructs a host agent how to rewrite flagged prose (style profiles, silence, preservation rules). That rewrite is performed by the host agent, not by the detector. It is not a feature point below. The detector, the contract, and the guard are the product.

## Non-functional constraints

- **Form factor:** A Python standard-library detector plus Node.js plugin hooks. No compiled extensions, native code, GPU, or accelerator are required or claimed. No runtime third-party libraries.
- **Language floor:** Python 3.9 or newer for the detector. Node.js for the hooks.
- **Platforms:** Linux, macOS, and Windows; Linux with a supported interpreter is the primary platform. Path, encoding, and line-ending behavior that the product already handles (UTF-16, UTF-8 byte-order mark, carriage-return/line-feed) remains an obligation on every platform.
- **Hardware:** CPU-only. The product runs on a real host that invokes the detector from this repository’s source tree and, for plugin features, runs the hooks with Node.js. There is no accelerator profile.
- **Network:** The runtime contains no network client and no telemetry. Analysis is local. This is a hard product constraint, not a fallback.
- **Privacy:** The plugin stores a one-word mode flag and a per-session ledger. A ledger whose last modification is more than seven days old is gone by the time a later session is in use; a ledger seven days old or younger is kept. Ledger files are written with owner-only permissions.
- **Scope of language:** English prose is the supported scope. The score describes patterns in that prose. It does not establish authorship, truth, or overall writing quality, and it must not be used to accuse a person.
- **Determinism:** The same extracted prose, on the same detector, produces the same report. There is no model and no random component in the default scan. The optional resampled interval (FP-01) is the sole opt-in extra; its presence or absence does not change the point score.

## Required substance (global)

Every feature point below is delivered by the real local detector or the real plugin hooks, on the machine, with no accelerator. The score is computed from the prose in front of the detector by the rules of FP-01; supported documents are extracted by FP-02 before scoring; the doctor's checks come from running the bundled detector.

## Non-goals

- Proving whether a model wrote a document. The score ranks writing; it is not a yes/no authorship classifier. Published comparisons of the score across collections of documents describe ranking, not per-document accuracy, and are not an obligation of the detector command.
- Reading PDF or RTF. Those extensions are logged as binary by the guard and yield no extracted text from the detector.
- Scoring a file written only by a shell command. That path reaches disk without passing Write or Edit; the guard does not see it. The writing contract still applies to whoever composed the text.
- A website, account, or hosted service.
- Consulting or optimizing against third-party authorship, plagiarism, or integrity detectors.
- Rewriting a `.docx`, `.epub`, `.odt`, or `.ipynb` in place when cleanup is requested. Cleanup prints extracted plain text; writing that back over the original would replace the document with loose text.
- Treating the bundled skill’s rewrite, silence, and style-profile instructions as a detector obligation. Those are instructions for a host agent.
- Treating the recorded-session demo, the documentation checker, the bundled evaluation script, or the status-line helper as product surfaces a first-time user must have.

## Feature points

### FP-01: Local detector scan, 0–100 score, and five bands

**Public entry:** The prosecheck detector command. The caller supplies a single file path, or supplies no path and pipes text on standard input. Optional switches: cleanup (FP-03), a resampled interval on the score, a request for the usage message, and a double-dash that stops option parsing so a file name may begin with a dash. This feature point is the report. Extraction of archives and notebooks is FP-02; the cleanup switch’s text output is FP-03.

**Normal behavior:**

- On readable non-empty extracted prose, the detector prints a structured report and exits successfully. The report has two kinds of content: **findings** and **metrics**.
- Each finding is one fired machine-checked pattern. It carries a human-readable label, a hit count, and up to three short samples drawn from the text. Catalogue numbers that did not fire are omitted. The nine catalogue numbers with no detector (7, 9, 28, 29, 43, 45, 49, 52, 53) never appear as findings.
- Metrics always include: how many characters were scanned (capped at 262,144); whether the extracted prose was longer than that window (it is not longer when it has at most 262,144 characters, and longer otherwise); the integer **score** from 0 through 100; the **band** name; a **confidence** label (`none`, `low`, `moderate`, or `high`) and, when confidence is not `high`, a reason that a caller can read; a count of fired findings; and character-layer counts for invisible/zero-width characters, non-standard spaces, and mixed-script lookalikes.
- The five bands, as ranges of the score, are: `clean` (0–20), `light tells` (21–40), `mixed` (41–60), `heavy tells` (61–80), `pervasive tells` (81–100).
- The catalogue holds 71 patterns, numbered 1 through 71, in seven groups. The detector’s machine-checked set is the 62 numbers that are not in the no-detector list above. Of those 62, **50 can move the score** and **12 are writing advice** (reported, weight zero): 4 (hyphenated cliché pairs), 19 (filler phrases), 22 (persuasive authority tropes), 41 (mechanical sentence-length alternation), 42 (opener repetition), 46 (semicolon and parenthesis underuse), 54 (hedge stacking), 55 (contraction absence), 58 (em-dash overuse), 60 (curly quotation marks), 61 (hyphen-for-en-dash in numeric ranges), and 68 (trailing / stray whitespace). A writing-advice finding never changes the score and never counts as a family for any floor or for confidence: a document scores the same as the same document without that phrasing whenever the score-moving findings are the same.
- Catalogue 17 has two forms, reported as two separate findings under that number. The **parallelism form** is weight-zero writing advice like the twelve above. It is a sentence that denies one framing and then asserts another in one of exactly these shapes: the contraction “it’s not just” or “it’s not merely” followed by “about”, “a”, or “an”; “not only” followed, within forty characters of the same sentence, by “but”; or “doesn’t just” followed, within forty characters and with no comma or period between, by “it”. The **tailing-negation form** is score-moving: a clause followed by a comma and a short “no …” tail of the stock kind (no guessing, no waste, no wasted motion, no hassle, no fluff, no stress, no jargon).
- The 71 catalogue titles are: (1) AI vocabulary; (2) model-dialect vocabulary; (3) promotional language; (4) hyphenated word-pair overuse; (5) “simple yet X” cliché; (6) stacked adjective chains; (7) rule of three overuse; (8) synonym cycling; (9) generic character naming in fiction; (10) significance inflation; (11) notability name-dropping; (12) vague attributions; (13) article-titles-as-proper-nouns; (14) conservation / ecosystem padding; (15) false ranges; (16) superficial -ing tail clauses; (17) negative parallelisms and tailing negations; (18) “Not X, just Y” / “No X, just Y”; (19) filler phrases; (20) empty pivot phrases; (21) outcome speculation tails; (22) persuasive authority tropes; (23) editorial interjections; (24) self-thoroughness phrases; (25) question-answer rhetorical pattern; (26) “concrete evidence” defense phrase; (27) compulsive intro hooks; (28) meandering intro; (29) prompt echo; (30) diff-anchored writing; (31) signposting and announcements; (32) cataloguing lead-ins; (33) inline-header vertical lists; (34) mid-essay bullet injection; (35) fragmented headers; (36) formulaic challenges sections; (37) transition cluster overuse; (38) compulsive conclusion phrases; (39) generic positive conclusions; (40) sentence-length monotony; (41) mechanical sentence-length alternation; (42) opener repetition; (43) avoidance of fragments and run-ons; (44) uniform paragraph length; (45) identical paragraph structure; (46) semicolon and parenthesis underuse; (47) chatbot artifacts; (48) sycophantic / servile tone; (49) RLHF / helpful-assistant register; (50) knowledge-cutoff disclaimers; (51) copula avoidance; (52) passive voice and subjectless fragments; (53) two-way passive-voice drift; (54) excessive hedging; (55) contraction absence; (56) boldface overuse; (57) emojis; (58) em-dash overuse; (59) title case in headings; (60) curly quotation marks; (61) hyphen-for-en-dash in ranges; (62) invisible / zero-width characters; (63) placeholder / Mad-Libs text; (64) chatbot reference-markup leak; (65) AI tracking params; (66) homoglyph / mixed-script confusables; (67) non-standard spaces; (68) trailing / stray whitespace; (69) canonical marketing-slop phrases; (70) decorative horizontal rules; (71) degenerate repetition. A finding’s label names its catalogue pattern in human-readable words; the wording is the implementer’s choice.
- Scoring counts **distinct catalogue families**, not hits. A document whose findings include exactly one score-moving family (sentence-length monotony and uniform paragraph length count as families here), however many hits it has, scores at most 40 (`clean` or `light tells`), unless the single-decisive floor below applies.
- A **decisive** finding is one of: invisible/zero-width characters (62), placeholder text (63), chatbot reference-markup leak (64), AI tracking params (65), mixed-script homoglyphs (66), article-title-as-proper-noun (13), chatbot artifacts (47), knowledge-cutoff disclaimer (50), sycophantic tone (48). Two distinct decisive families in one scan raise the score to **at least 65**. A single decisive family raises it to **at least 45** only when confidence is above `low`. A single decisive family at `none` or `low` confidence does not take that 45 floor.
- On a document shorter than 120 words, two distinct score-moving families among catalogue numbers 1–39, 47–51, and 69 raise a floor of 25, and three or more raise a floor of 45. On a document of 400 words or more, five distinct score-moving families of any number raise a floor of 25, and six or more raise a floor of 45. Words are runs of letters, digits, apostrophes, and hyphens.
- **Rhythm kinds** are sentence-length monotony (40), mechanical alternation (41), uniform paragraph length (44), and contraction absence (55). Mechanical alternation and contraction absence are writing advice. A document whose only score-moving findings are rhythm kinds scores at most 40; a document with no score-moving finding other than sentence-length monotony scores in `clean` (at most 20). Sentence-length monotony fires when a document has at least three sentences and the coefficient of variation (population standard deviation divided by mean) of their word counts is below 0.35. Uniform paragraph length fires when a document has at least four blank-line-separated paragraphs and the coefficient of variation of their word counts is below 0.4.
- Confidence is `none` below 40 words; `low` below 120 words, or below 300 words with only one score-moving family; `moderate` below 300 words otherwise; `high` at 300 words or more. The saved-file guard (FP-05) treats `none` as “do not nudge,” even if the point score is above the threshold.
- Inside the scan window, these generate no findings: fenced and indented code blocks as CommonMark defines them (including how a fence closes and how an indented line that continues a paragraph stays paragraph text), inline code spans, runs of two or more consecutive blockquote lines, markdown table rows, badge lines (lines made only of linked badge images), and YAML front matter at the start of the text.
- A banned word that is split only by in-word zero-width characters still fires the same finding as the unsplit word. A mixed-script lookalike inside a Latin word both fires mixed-script homoglyphs (66) and still matches the same vocabulary finding as the ASCII spelling.
- **Family rules.** Lexical families match whole words and phrases without regard to letter case unless a rule says otherwise, and an inflected form of a listed verb or noun is the same word. Each machine-checked family fires on these conditions:
  - **AI vocabulary (1):** additionally, align with, crucial, delve, tapestry, pivotal, vibrant, meticulous, testament, underscore, intricate, intricacies, interplay, garner, bolster, foster, showcase, emphasize, enduring, enhance, leverage, utilize, facilitate, encompass, harness, holistic, paradigm, transformative, unprecedented, myriad, plethora, robust, seamless, navigate, embark, craft, landscape, journey, realm, multifaceted, elevate, empower, unlock, and “capture the essence / spirit / imagination / heart / magic”. Every word of the writing contract’s banned-vocabulary list (FP-04) is in this family except the model-dialect words below and the two context-only words named in FP-04.
  - **Model-dialect vocabulary (2):** genuinely, fascinating, nuanced, thoughtfully, refreshingly, strikingly, compellingly, “quietly powerful / profound / radical”, “deeply human / personal / felt / unsettling”, “resonates deeply”, game-changer (and other game-changing forms), supercharge, skyrocket, turbocharge, revolutionize, “double down on”, “dive deep(er) into”, “unlock (the) power / potential / value”, and “take … to the next level”. It fires only when a document has two or more of these hits combined.
  - **Promotional language (3):** brochure and résumé puffery: nestled, breathtaking, must-visit, stunning, picturesque, charming, idyllic, vibrant community, rich cultural heritage, in the heart of, world-class, top-tier, unparalleled, premier, leading, esteemed organization, valuable asset, passion for excellence, proven track record, results-oriented, wealth of experience, dynamic team, fast-paced environment, deeply passionate, perfectly situated, close-knit or tight-knit team, “I am excited to apply / bring”, uniquely positioned to. Three or more sentences that each open with a marketing imperative verb (install, join, grab, download, try, discover, experience, escape, transform, reclaim, unlock, elevate, boost, say, imagine, explore, meet, introducing, upgrade, claim, unleash, supercharge, level, stop, start) also fire it.
  - **“Simple yet X” (5):** “simple yet” followed by effective, powerful, profound, elegant, transformative, sophisticated, or beautiful.
  - **Stacked adjective chains (6):** a run of four or more words joined by commas (or a final “and”) that ends in a noun, where at least one of the chained words is adjectival: a stock evaluative adjective of promotional prose, or a word with an adjective ending (-ive, -ous, -able, -ible, -ic, -ical, -ant, -ent, -ful, -less, -al, -ial, -ary, -ory, -ish).
  - **Synonym cycling (8):** three or more members of one synonym cluster, singular or plural, each used as a whole word: protagonist / main character / central figure / hero / heroine; company / firm / organization / enterprise / business; author / writer / novelist / scribe; report / study / analysis / investigation / examination; technology / tool / system / platform / solution; technique / method / approach / strategy / tactic; challenge / obstacle / difficulty / hurdle / barrier; benefit / advantage / upside / strength.
  - **Significance inflation (10):** stock collocations that inflate importance: “stands / serves (or stood / served) as a testament / reminder / symbol / beacon / cornerstone / bridge / gateway / hallmark”; “underscores / highlights (or underscoring, highlighted, and the like) its / the / their / his / her importance / significance / enduring / central / vital / crucial / pivotal / key …”; “reflects a broader trend / shift / pattern”; “marks a turning point / milestone / watershed / new chapter / new era”; “symbolizes”; “sets the stage for”; “left an indelible mark”; “plays a crucial / pivotal / vital / key / central / significant role”; “has shaped / sparked”, “has come to define / symbolize”.
  - **Vague attributions (12):** experts argue / believe / say / claim / note / suggest; industry reports / observers / analysts; observers have cited / noted; some critics argue; researchers have found; studies suggest; it is widely believed.
  - **Article-title-as-proper-noun (13):** “The List / Index / Compilation / Collection / Catalogue / Guide / Overview of <title> is a / an / the”, where the title is a run of words.
  - **Conservation / ecosystem padding (14):** “plays a vital / crucial / key / significant role in its / the ecosystem”, “conservation efforts are underway / ongoing / in place”, “serves as an indicator species”, “contributes to biodiversity”.
  - **False ranges (15):** only the rhetorical sweep between a beginning and a grand or present-day end: “from the dawn / birth / earliest days / inception / advent / emergence / humble …” followed within the sentence by “to the modern / present / current / contemporary / digital / future / mighty / vanished / towering …”, or “from (the) humble …” followed by “to (the) mighty / towering / grand / sprawling …”.
  - **Superficial -ing tails (16):** a comma followed by highlighting, reflecting, symbolizing, emphasizing, underscoring, showcasing, fostering, cultivating, encompassing, signaling, demonstrating, illustrating, representing, suggesting, indicating, reinforcing, leveraging, aligning, embodying, exemplifying, or epitomizing.
  - **“Not X, just Y” (18):** a denial immediately corrected after a comma: “no / not <word>, just / only / simply <word>”, or “not / isn’t / aren’t / wasn’t / weren’t just / merely (a / an / the) <word>,” (or a dash) followed by “it’s / it is / it was / they’re / they are / they were / that’s / but”. A sentence of the second shape may also carry the parallelism form of 17 under the rule above.
  - **Empty pivot phrases (20):** “it’s worth noting / mentioning that”, “it bears noting / mentioning that”, “one thing to consider / keep in mind is”, “it is interesting to note that”, “a key consideration is”, “a point to highlight is”.
  - **Outcome-speculation tails (21):** a comma followed by raising questions about, prompting reflection on, sparking debate about, with broader implications for, reshaping our understanding of, paving the way for, or signaling a shift toward.
  - **Compulsive intro hooks (27):** “in today’s (up to two words) world / landscape / environment / market”, “in a world where”, “in an era of”, “in recent years,”, “more than ever before”, “we live in a time / world when”, “great / exciting / big news” followed by “!” or “:”, “ever wanted / wondered / dreamed / wished to …?”, “in an increasingly interconnected / digital / competitive / complex world”.
  - **Formulaic challenges (36):** “despite these / its / the challenges / obstacles”, “challenges and (future) prospects / outlook / legacy”, “continues to thrive”, “typical of emerging / urban / modern”, “faces several / many / numerous challenges”.
  - **Transition clusters (37):** two or more sentence-opening transitions (Additionally, Furthermore, Moreover, However, Nevertheless, Consequently, Subsequently, Notably, capitalised, at the start of the text, of a line, or after sentence-ending punctuation) in one paragraph.
  - **Compulsive conclusions (38):** a line that opens with in conclusion, overall, in summary, to summarize, to conclude, all in all, in essence, or ultimately.
  - **Generic positive conclusions (39):** the future looks bright; exciting times lie ahead; journey toward excellence; step in the right direction; “(the) outlook / future (for …) is / looks / remains bright”; well-positioned (or well positioned) for whatever comes next / the future / the road ahead.
  - **Filler phrases (19):** in order to, due to the fact that, at this point in time, in the event that, has the ability to, it is important to note that, it should be mentioned that, needless to say.
  - **Persuasive authority tropes (22):** here’s the thing, make no mistake, the truth is, let’s be honest, the simple fact is, at its core, what really matters, more than anything, at the end of the day, the bottom line is, in reality, “fundamentally,”, the real question is, the heart of the matter, the deeper issue, when you get down to it, when all is said and done.
  - **Self-thoroughness phrases (24):** this comprehensive guide / overview / analysis, this in-depth analysis / look / examination, this complete guide / overview, a thorough examination of, everything you need to know about.
  - **Opener repetition (42):** within one paragraph of at least three sentences, three or more sentences open with the same first two words.
  - **Chatbot artifacts (47):** assistant-voice phrases: I hope this helps; “Certainly!” and “Of course!” (with the exclamation mark); let me know if you; would you like me to; feel free to ask / reach out; happy to help (at a sentence end); “here / below is (a / an / the) overview / summary / rundown / recap / brief”; “here are / here’s a few / some / two / three options / drafts / versions / variations”; “here is (or here’s) a draft”; “depending on the vibe / tone / style”; “I hope (this email) finds you well”; “as an AI / LLM / AI assistant / AI language model / large language model / language model”; and chat residue in a deliverable (“to answer / address your question”, “in response / answer to your question”, “your question about / regarding / concerning”, “as (you) requested / asked, here”, “here is (the) draft / first pass / revised version of / for your”).
  - **Sycophantic tone (48):** “you’re / you are absolutely right”, or praise of the question immediately followed by “!”, “.” or “,”: great question, excellent point, “what a thoughtful / great / wonderful / fantastic question”, “that’s a great / wonderful / fantastic / brilliant / excellent point / question”. These phrases fire 48 and not 47.
  - **Knowledge-cutoff disclaimers (50):** “as of my (last) training / knowledge”, “up to my (last) training / knowledge”, “while specific details are limited / scarce / not extensively (or widely) documented”, “based on (the) available information”, “as of my (knowledge) cutoff”, and speculative privacy filler about a person (“maintains a low profile”, “keeps his / her / their personal life private”, and the like).
  - **Copula avoidance (51):** serves as, stands as, functions as, acts as, “represents a / the”, “marks a / the”, boasts, “features” followed by an article, a number or a quantity word, “offers a”, refers to.
  - **Hedge stacking (54):** two or more hedges in one sentence, where the hedges are the lower-case words may, might, could, possibly, potentially, arguably, perhaps, “seem(s) (to / like)”, “appear(s) to”, somewhat, relatively, fairly, “kind of”, “sort of”.
  - **Invisible / zero-width characters (62):** every invisible character that character cleanup (FP-03) removes, counted on the scan window: format characters, control characters other than tab, line feed, and carriage return, TAG characters, variation selectors, joiners, and the other default-ignorable or filler codepoints that render as nothing, except where FP-03 says the character does a job in its position.
  - **Placeholder text (63):** template slots left in the text: a square-bracket slot that is a fill-in instruction or a field left to fill (it begins with your, insert, add, enter, placeholder, todo, tbd or tk, or it names a person, company, client, place, or source to be filled in); an all-capitals bracketed slot, other than the short letter-and-numeral labels that scientific and mathematical writing puts in brackets; a double-brace template field; a run of three or more x; and lorem ipsum. A bracket that is immediately followed by “(” or “[” is a link, not a slot.
  - **Chat reference markup (64):** chat-interface citation tokens: words beginning cite followed by turn, start or nav; words beginning oai_citation; contentReference; navlist; and bracketed 【number†…】 markers.
  - **AI tracking parameters (65):** a `utm_source` whose value is exactly one of chatgpt.com, chat.openai.com, perplexity.ai, claude.ai, gemini.google.com, copilot.microsoft.com, or poe.com. The value is the host name after the equals sign, up to the first character that cannot continue a host name and without a sentence-ending period; it fires only when that whole host name is one of those domains.
  - **Homoglyphs (66):** a whitespace-delimited token containing a run of letters that mixes ASCII Latin letters with letters of another script drawn like a Latin letter — the Cyrillic, Greek, Armenian, and Arabic-presentation lookalikes of a, c, d, e, g, h, i, j, n, o, p, s, u, v, w, x, y and of A, B, C, E, H, I, J, K, M, N, O, P, S, T, X, Y, Z — and contains no other non-ASCII letter.
  - **Non-standard spaces (67):** every space separator other than U+0020 that character cleanup (FP-03) normalizes; a no-break space that cleanup keeps is not counted, and a no-break space is never an invisible character (62).
  - **Trailing / stray whitespace (68):** spaces or tabs before a line end, any space or tab at the end of the text, two or more newlines at the end of the text, or any whitespace before the first character. A single final newline does not fire it.
  - **Hyphenated word-pair overuse (4):** stock hyphenated compounds of business and marketing prose (hyphenated clichés of the brochure and résumé kind); which compounds are on the list is the implementer’s choice. An ordinary hyphenated word that is not such a stock compound, and a numeric range, do not fire it.
  - **Notability name-dropping (11):** a credit verb (featured, profiled, covered, cited, mentioned, highlighted, showcased) with “in” or “by” followed, in the same sentence, by a list of two or more named outlets; a follower count offered as evidence; and stock claims of a strong or active online, digital, or social-media presence, of being widely covered, or of independent coverage.
  - **Editorial interjections (23):** “it’s / it is important to remember / note / understand / recognize”, “one must note that”, “it is worth pointing out”, “it cannot be overstated that”, “it must be emphasized that”.
  - **Question-answer rhetorical pattern (25):** a short question that opens with an auxiliary or modal verb and is answered at once by a one-word reply sentence (an answer word such as yes, no, absolutely, never, maybe, probably, or always, followed by a period or an exclamation mark). A question that is not answered that way does not fire it.
  - **“Concrete evidence” defense phrase (26):** stock demands for, or dismissals for want of, concrete evidence or proof: “without concrete evidence”, “do you have concrete evidence”, “I (would) need concrete evidence / examples to”, “absent concrete proof”, “provide concrete evidence”.
  - **Diff-anchored writing (30):** describing something by how it differs from an earlier version instead of as it now is: “unlike the previous / prior / old / earlier version / release / implementation / approach”; “the / this (latest / new) update / release / version / change / patch / design adds / introduces / brings / delivers / includes / provides / improves”; “has / have been updated / refactored / improved / enhanced / changed to”; “previously … now”; “wasn’t / weren’t there before”; “we’ve / we have (now) added / removed / replaced / refactored / migrated”.
  - **Signposting and announcements (31):** “let’s dive / delve / explore”, “let’s break this / it down”, “here’s what you need to know”, “without further ado”, “now let’s look at”, “buckle up”, “stay with me”, “(are you) ready to dive in”.
  - **Cataloguing lead-ins (32):** a verb of use (used, uses, employs, employed, relied on, utilizes) followed by several, various, a number of, multiple, different, many, or numerous and a noun; a sentence that opens with “These”, an optional noun, and provide / offer / give / reveal / show / allow / enable / help followed by information, insight, understanding, details, or data; and a definitional metaphor: is / are / was / were / remains / becomes (the / a) language, currency, architecture, heartbeat, lifeblood, DNA, backbone, bedrock, engine, scaffolding, or connective tissue “of”.
  - **Inline-header vertical lists (33):** a line, or a list item, that opens with a bold run closed by a colon inside the bold or right after it.
  - **Mid-essay bullet injection (34):** in a document that has no markdown heading, at least one paragraph made only of bulleted or numbered lines alongside two or more prose paragraphs. A document with a heading, or with no such list paragraph, does not fire it.
  - **Fragmented headers (35):** a markdown heading whose next non-blank line is a very short plain line (not a heading, list item, or table row, and only a few words long) that repeats a word of the heading.
  - **Semicolon and parenthesis underuse (46):** checked only on long documents — a document under 300 words never fires it — and fires when such a document has no semicolon and almost no parenthetical.
  - **Contraction absence (55):** checked only in first-person or opinion writing, where first-person pronouns make up a noticeable share of the words; it fires when most of the forms that could be contracted are written out in full. Prose with no first-person voice never fires it.
  - **Mechanical sentence-length alternation (41):** a run of six or more sentences whose lengths go up and down in strict alternation nearly every time, with lengths that differ substantially.
  - **Boldface overuse (56):** bold spans (text between double asterisks) in prose.
  - **Emojis (57):** emoji and pictographic symbol characters.
  - **Em-dash overuse (58):** two or more em dashes in one paragraph.
  - **Title case in headings (59):** a markdown heading of three or more words whose major words (all words other than articles, short prepositions, and conjunctions; at least two of them) all begin with a capital letter. A heading in all capitals, or one that begins with a digit or a symbol, does not fire it.
  - **Curly quotation marks (60):** any typographic (curly) single or double quotation mark.
  - **Hyphen-for-en-dash in numeric ranges (61):** a range between two years written with a hyphen: an earlier year, a hyphen, and a later year.
  - **Canonical marketing-slop phrases (69):** fixed marketing collocations that survive vocabulary changes: unlocking full potential, navigating the complexities, a testament to the power or importance of, staying ahead of the curve, turning challenges into opportunities, taking something to the next level, harnessing the power of, paving the way for, saying goodbye to, imagining a world where, and others of that fixed kind; the full list is the implementer’s choice. Prose that uses none of these stock collocations does not fire it.
  - **Decorative horizontal rules (70):** three or more standalone horizontal-rule lines used as section furniture in a document of a couple of dozen lines or more. One or two rules, or rules in a short document, do not fire it.
  - **Degenerate repetition (71):** the same multi-word span emitted again and again, so that a large share of the document’s runs of six consecutive words (on the order of a fifth or more) occur more than once. Ordinary repetition of a term, a name, or a short phrase does not fire it, and a document in which no run of six consecutive words occurs twice never fires it.
- A leading byte-order mark and carriage-return/line-feed line endings are not invisible characters and add no finding. A zero-width character inside the text is an invisible character.
- When the resampled-interval switch is on and the document has at least four sentences, metrics include a low/high interval on the score. With fewer than four sentences, the interval is omitted and the metrics state that there are too few sentences. The interval does not replace the point score. The resampling count and seed are the implementer’s choice.

**Boundary / error behavior:**

- Empty extracted prose does not print a report. Every source of empty extracted prose (empty standard input, a file that decodes to nothing or to whitespace only, a notebook with no markdown cells, an archive with no extractable prose, PDF, RTF, and a buffer that is not text) is one failure kind: a structured error on the error stream, a failing status, and no traceback.
- An unreadable path, or a file whose extension is a supported archive type but whose bytes are not a readable zip, is a second failure kind: a structured error on the error stream, the same failing status as empty input, and no traceback.
- An unknown option fails with a distinct failing status and a structured error that identifies the unknown option and points at help.
- Help (the help switch or the short help alias) prints the usage message to standard output and succeeds. Usage names the cleanup switch, the interval switch, the double-dash, and the single-file operand.
- Two or more file operands still succeed: the first file is scanned, and the error stream notes that only the first file was scanned and names that file.
- Extracted prose longer than 262,144 characters is still scored: metrics report that it is longer than the window and that 262,144 characters were scanned. Extracted prose of at most 262,144 characters is not longer than the window. Findings, including character-layer findings, are computed only on the window. A homoglyph or invisible character that sits only past the window does not appear as a finding.
- A binary-looking buffer that is not UTF-16 and contains a NUL byte is treated as not text: it yields empty input (failure), not a report full of invented invisible-character hits. UTF-16 with a byte-order mark is decoded as text.
- Standard input and standard output use UTF-8. Cleanup (FP-03) preserves the input’s newline convention on output so a file that arrived with carriage-return/line-feed still has it.

### FP-02: Twenty-format extraction, size caps, and the 262,144-character window

**Public entry:** The same detector command as FP-01, when the operand is a file whose extension is one of the twenty supported formats, and the saved-file guard (FP-05) / `/prosecheck check` (FP-06) when they accept a path. This feature point is **getting prose out of the file** and **refusing or truncating** when the file is too large or not readable as prose. Scoring of the extracted text is FP-01.

**Normal behavior:**

- The twenty supported formats are exactly: `.md`, `.mdx`, `.markdown`, `.txt`, `.text`, `.rst`, `.tex`, `.org`, `.adoc` (plain text); `.docx`, `.docm`, `.pptx`, `.pptm`, `.xlsx`, `.xlsm`, `.odt`, `.odp`, `.ods`, `.epub` (zip-based documents); and `.ipynb` (notebook). Plain text is accepted up to **512 KB**. Zip-based documents and notebooks are accepted up to **4 MB**. Those caps are file size on disk, as the guard and `/prosecheck check` enforce them, in binary units: a kilobyte is 1,024 bytes, so the plain-text cap is 524,288 bytes and the zip/notebook cap is 4,194,304 bytes (4 MB, which is 4096 KB). A file whose size equals its cap is accepted; one byte more is over the cap. The detector command itself reads a path it is given; the plugin refuses oversize files before scoring (FP-05, FP-06).
- For the nine plain-text extensions, the extracted prose is the decoded file body (UTF-8 with optional leading byte-order mark, or UTF-16 with a byte-order mark). A leading mark is not part of the prose and is not an invisible-character finding.
- For `.docx` / `.docm`, visible paragraph text of the main document is extracted, without XML markup.
- For `.pptx` / `.pptm`, visible text of slides is extracted in slide order, without markup.
- For `.xlsx` / `.xlsm`, cell text is extracted sheet by sheet and, within a sheet, in cell order. Shared-string cells, inline-string cells, and string-typed cells (including formula caches that hold a string) are read. A shared-string cell contributes the shared-string table entry its index names; an index that is not a whole number naming an entry of that table contributes nothing. Adjacent cells stay separated (a line or cell boundary between them). A numeric cell is not required to become prose.
- For `.odt`, `.odp`, and `.ods`, visible text of the content document is extracted. Linked text, spans, explicit space runs, tabs, and line breaks are preserved as ordinary spaces, tab characters, and newlines. Markup is not leaked.
- For `.epub`, chapter HTML/XHTML documents are read in the natural order of their member names in the archive (runs of digits compare as numbers). Navigation, style, and script content are excluded. Inline emphasis and links contribute their visible text, not their tags. A chapter is not dropped because of namespace irregularities in its attributes.
- For `.ipynb`, only markdown cells are extracted, joined as prose. Code cells, outputs, and comments inside code are not prose and must not appear in the extraction.
- Extraction yields the same visible words as the plain-text version of that prose, so a supported document scores like its prose would as plain text (FP-01).
- XML markup characters from the archive must not appear in the extracted prose.
- The extracted prose of a zip-based document or a notebook does not begin or end with whitespace. Line breaks separate consecutive paragraphs, slides, cells, chapters, or markdown cells; nothing is added before the first text or after the last, and whitespace at either end of the extracted text is dropped. A single paragraph therefore extracts as exactly its visible text. The 262,144-character window, and whether the extracted prose is longer than it, are measured on that text.

**Boundary / error behavior:**

- `.pdf` and `.rtf` are not among the twenty formats. The detector treats them as having no extracted prose (empty input, FP-01). The guard does not score them; it records them on the session ledger as binary (FP-05).
- A file named like a supported archive whose bytes are not a zip fails the detector with a structured error and no traceback (FP-01). An archive that is a zip but has no extractable prose yields empty input.
- A notebook that is not valid JSON, or whose cells are not a list of objects with string (or list-of-string) markdown sources, yields empty extracted prose. The detector command then fails as empty input. It does not print a traceback.
- The archive-member size cutoff is the implementer’s choice.
- The 262,144-character window is measured on the extracted prose, not on the compressed archive. Character-layer rules (62, 66, 67, 68) use that same window: an invisible character placed only after character 262,144 is not a finding.
- Source-code extensions (for example `.py`, `.js`) are not among the twenty formats. The guard leaves them alone (FP-05). If the detector command is aimed at such a file anyway, it is read as plain text; that is not a plugin obligation.

### FP-03: Deterministic character cleanup

**Public entry:** The detector command with the cleanup switch, on a file path or on standard input. Without the switch, the same character layer is **reported** as findings 62, 66, 67, and 68 and as metrics counts (FP-01); it is not applied to the text. This feature point is the switch that **emits scrubbed text instead of the report**.

**Normal behavior:**

- Cleanup prints the scrubbed text to standard output and exits successfully. It does not print the structured report.
- What is removed: every invisible character (format characters, control characters other than tab, line feed, and carriage return, TAG characters U+E0000–U+E0FFF, variation selectors, zero-width joiner and non-joiner, and the other default-ignorable or filler codepoints that render as nothing) except where it does a job in its position. A character does a job, and is kept, in exactly these positions: a TAG character inside an emoji tag sequence (a black-flag base, tag characters, and the cancel tag); an ideographic variation selector after a CJK ideograph; a zero-width space beside a character of a script written without spaces (Thai, Lao, Khmer, Myanmar, kana, CJK); a soft hyphen between two letters; a bidirectional mark or control in a document that contains right-to-left script; a Mongolian selector after a Mongolian letter; a Khmer inherent vowel beside Khmer; a zero-width joiner or non-joiner beside a letter of a script that joins (Hebrew and Arabic blocks, Indic scripts, Myanmar, Khmer) or beside an emoji or symbol; and a variation selector after an emoji, a symbol, or a CJK ideograph, or before a combining keycap. After cleanup, a rescan (FP-01) reports zero invisible-character hits.
- What is normalized: every space separator other than U+0020 becomes U+0020, except a no-break space (U+00A0) or narrow no-break space (U+202F) that holds something together: one with a digit on either side, one before `:` `;` `!` `?` `»` `›` `%` `€`, or one after `«` `‹`. Line and paragraph separators become line feeds. After cleanup, a rescan reports zero non-standard-space hits.
- What is folded: inside a run of letters that mixes ASCII Latin letters with Latin-looking letters of another script and holds no other non-ASCII letter (the homoglyph condition of FP-01, catalogue 66), each lookalike becomes its ASCII letter. Runs that do not meet that condition, including whole non-Latin words, sentences, and web addresses, are not folded.
- What is trimmed: spaces and tabs at the end of every line, leading blank lines, and all whitespace at the end of the text; then, when the input ended in a line feed, exactly one line ending is restored. The first line’s own indentation is kept. Tabs, line feeds, and carriage returns inside the body are never removed as invisible characters.
- Cleanup agrees with detection: a character the scrub keeps is not counted as an invisible character or a non-standard space on a scan of the original, and a character it removes or normalizes is counted. Visible text, combining marks, and every genuine non-Latin word stay byte-for-byte.
- The detector command, with or without cleanup, finishes within **8 seconds** on any input inside the plain-text size cap, including inputs made of long runs of invisible characters or spaces — the same budget the saved-file guard gives plain text (FP-05).
- For `.docx`, `.epub`, `.odt`, or `.ipynb`, cleanup prints the extracted plain text, not a rebuilt document, and does not write the original path. After the process exits, that path’s bytes equal the bytes from before the run.

**Boundary / error behavior:**

- Empty input, unreadable files, unknown options, and extra file operands follow FP-01. Cleanup does not turn empty input into success.
- Cleanup never invents words, never deletes a Latin letter that was actually there, and never converts a genuine Cyrillic word into Latin lookalikes.
- Trailing whitespace at end of line is removed even when two spaces were meant as a markdown hard break. That collapse is required, not optional.

### FP-04: Always-on writing contract at session start, on the prompt, and in a subagent

**Public entry:** The plugin’s session-start, prompt-submit, and subagent-start hooks, as a host agent fires them: JSON on standard input, text or a JSON envelope on standard output. `/prosecheck init` (FP-06) writes the same contract into the project for agents that are not Claude Code. This feature point is **placing the contract in context**. Scoring a saved file is FP-05. Changing the level is FP-06.

**Normal behavior:**

- When the level is `lite`, `full`, or `strict` (the default when no flag has been stored is `full`), session start emits the writing contract for that level. When the level is `off`, session start emits nothing.
- The contract’s scope is prose deliverables only (documents, README/markdown prose, CVs, cover letters, emails, reports, essays, articles, drafted text the user will publish or send). The contract never says it applies to source code. It names what it never touches (code comments, commit messages, JSON/YAML/config, CLI output, logs, error messages, the conversational register of chat) and composes with other modes (a chat-compression mode owns chat; a code-simplicity mode owns code; this contract owns deliverable prose).
- The contract’s prose rules, so a host agent can follow them, include: vary sentence length irregularly (no metronome, no mechanical short-long alternation); a banned-vocabulary list that includes delve, tapestry, pivotal, crucial, leverage, robust, seamless, foster, underscore, showcase, landscape (abstract), journey (abstract), realm, multifaceted, holistic, testament, vibrant, comprehensive, plethora, myriad, boast, elevate, empower, unlock, game-changer, supercharge, genuinely, fascinating, nuanced; banned moves including rule-of-three flourishes, “it’s not just X, it’s Y”, hedge stacking, signposting (“let’s dive in”), empty pivots (“it’s worth noting”), “In conclusion / Overall” closers, outcome-speculation tails, self-thoroughness, generic upbeat endings, and chatbot phrases (“I hope this helps”); em-dash at most once per paragraph; no bold-for-emphasis inside prose sentences; no emojis in prose; factual/encyclopedic content stays neutral third person; first-person/opinion content may contract; preserve numbers, units, dates, proper nouns, citations, quotes, technical terms; never invent facts; end sections on a fact or observation; silent — never announce the contract, never name prosecheck, never report a score, a band, a pattern list, or a rewrite pass, and do not offer a style choice.
- Every word on that banned-vocabulary list, used as a standalone word in otherwise ordinary prose, fires a machine-checked family of FP-01 under that family’s rule (AI vocabulary; model-dialect vocabulary, which needs two hits, for its dialect words), so the guard can enforce the list. “Comprehensive” and “boast” are the two exceptions: they stay on the banned list and are enforced only in context (self-thoroughness phrases, copula avoidance), not as bare words.
- In `full` and `strict` (not `lite`), the contract also tells the host, after writing a prose file, to run the detector on that file and to fix flagged spans (at most two fix passes, keeping rhythm variation) when the band is worse than the target. At `full` — stored, or because no flag is stored, or because nothing valid is stored (including an unreadable flag, unless the environment supplies another of the four words) — the targets are `clean` or `light tells` (score at most 40). `lite` carries neither that step nor those targets. `strict` sets the target to the `clean` band (score at most 20) and also asks for a finish through the cleanup switch (FP-03), which `full` does not carry.
- On the **first** session start of a fresh install — when no mode flag exists yet and the flag can actually be written — a one-time welcome is prepended to the contract. The welcome states that saved prose is scored against 71 patterns, that plain text is accepted up to 512 KB and archives up to 4 MB, that the detector scores the first 262,144 characters, and that `/prosecheck doctor`, `/prosecheck check`, `/prosecheck off`, and `/prosecheck help` exist; it also says that prosecheck is installed and on, that there is no website and no upload, and that it is shown once. A later start on the same config directory, and a start whose flag cannot be written, carry no welcome.
- When session start runs with a level of `lite`, `full`, or `strict` (including the default `full` when no flag existed), later hooks on the same install see that stored level.
- When a user prompt is submitted and the prompt is not a `/prosecheck` command (FP-06), and the level is not `off`, the prompt-submit hook returns a short reminder that names that live level and says that prose deliverables follow the contract while code, config, and commits are untouched. When the level is `off`, the hook emits nothing.
- When a subagent starts and the level is `lite`, `full`, or `strict`, the subagent-start hook returns the **same contract** inside the JSON envelope the host keeps for a subagent-start event. When the level is `off`, the hook emits nothing. Session-start context does not reach a subagent on its own; without this hook, delegated prose would be unguarded.

**Boundary / error behavior:**

- A hook that receives malformed JSON, cannot read the mode flag, or meets any other internal error still exits successfully. It must not fail the host session. Malformed input is treated as an empty object.
- Any stored value other than `off`, `lite`, `full`, or `strict` is ignored. When nothing valid is stored, the level is `full`, unless the environment supplies one of those four words, in which case that word is used.
- The contract placed in a live session on this machine is allowed to name this machine’s detector path; whether it does is the implementer’s choice. The contract **exported** by `/prosecheck init` (FP-06) must not name that path or the user name: it is portable.

### FP-05: Saved-file guard on supported file-edit tools

**Public entry:** The plugin’s post-tool-use hook, fired after Write, Edit, MultiEdit, NotebookEdit, or apply_patch. The host sends JSON on standard input that names the tool and the path (Write, Edit, and MultiEdit: a file path; NotebookEdit: a notebook path; Codex-style apply_patch: a patch body whose lines begin with three asterisks, a space, and then “Add File”, “Update File”, or “Move to”, then a colon, and the path is the remainder of that line after the colon). Surrounding whitespace on that path does not change which file is named. Whether a line with the same beginning and verb but no colon also names a path, and whether a NotebookEdit payload that carries a file path and no notebook path is scored, are the implementer’s choice. A line that only contains those words and does not begin with three asterisks does not name a path. The hook resolves relative paths against the working directory in that payload when one is supplied. This feature point **scores a just-saved prose file and nudges when it is flagged**. The score itself is FP-01. Which formats are prose is FP-02.

**Normal behavior:**

- When the level is `off` or `lite`, the guard emits nothing and does not score. When the level is `full` or `strict`, it scores eligible files.
- Eligible extensions are the twenty formats in FP-02. Other extensions produce no nudge. `.pdf` and `.rtf` produce no nudge; they are recorded on the session ledger as binary and are not re-scored.
- The default threshold is **40** (`full`). In `strict` it is **20**. A file is flagged only when the score is **strictly above** the threshold **and** confidence is not `none`. Zero-confidence results never nudge.
- On a flagged file, the hook prints a JSON envelope whose extra context names prosecheck, the file’s **base name**, the hook phrase for that score (`reads clean` / `reads mostly clean` / `reads with some AI tells` / `reads with heavy AI tells` / `reads with pervasive AI tells`), the integer score, the band, and up to five fired pattern labels, and asks for the flagged spans to be fixed. If the scan was truncated, that context names the 262,144-character window and says that only that prefix was included; otherwise that note is absent.
- On an unflagged eligible file, the hook emits nothing (no envelope). The save is not blocked.
- Every supported tool leads to the same scoring: a file yields the same kind of nudge, or the same silence, whichever of Write, Edit, MultiEdit, NotebookEdit, or apply_patch saved it. A notebook saved through NotebookEdit is scored on its markdown cells (FP-02).
- Paths under `node_modules`, under `.git`, or under a `memory` directory are skipped, including zip-based files there. Files that live inside the plugin’s own install tree are skipped. Instruction-file names that are exactly `claude.md`, `claude.local.md`, `agents.md`, `agents.local.md`, `skill.md`, or `memory.md` (any case) are skipped; those stems without a prose extension are skipped as well. A skipped instruction file is not recorded on the ledger at all, not even as binary. Only those exact names and those stems with a non-prose extension are instruction files; any other file is eligible by its extension.
- An apply_patch payload that names several files is scored one file at a time, at most **16** distinct paths. Each flagged file’s nudge is concatenated.
- Every eligible attempt is recorded on the session ledger for that session id: scored (score, band, labels, flagged bit, truncated bit), skipped for size (with the cap that was applied), failed (with a short reason), or binary. The ledger holds the **base name** only. At most the newest 20 records are kept. `/prosecheck show` (FP-06) reads this ledger.
- A plain-text file is given **8 seconds** of detector time; an archive or notebook is given **15 seconds**. Those budgets are the product’s published caps. A timeout is recorded as a failed check, not as a hang of the host.

**Boundary / error behavior:**

- A payload that names no path at all — no file path, no notebook path, and no apply_patch path line — is ignored (no nudge, successful exit, nothing recorded). A directory or other non-file is ignored the same way. A path that names something not on disk is recorded as a failed check for being unreadable, still with no nudge and a successful exit.
- A plain-text file larger than 512 KB, or an archive/notebook larger than 4 MB, is not scored. The ledger records a skip for size with that limit. `/prosecheck show` reports that the file was not scored because it exceeds the limit, in kilobytes.
- A failed check is recorded with a reason a user can read, and these five stay distinguishable from one another: Python cannot be found; the detector prints text that is not a structured report; the report is structured but has no numeric score; the detector times out; the detector produces no output or exits without a usable result. An empty result shares that last reason with the exit that yields no usable result, and that shared reason is not the unusable-report reason. Whether a file that cannot be read uses that same last reason or another user-readable reason is the implementer’s choice. The hook still exits successfully and prints no nudge. `/prosecheck show` lists those failures.
- Malformed input still exits successfully and prints no nudge.
- A file written only by a shell command is not seen, because this hook is not fired for that tool (non-goal).

### FP-06: `/prosecheck` commands — levels, check, doctor, show, init, stats

**Public entry:** The plugin’s prompt-submit hook, when the prompt is `/prosecheck` or `/prosecheck:prosecheck`, optionally followed by a subcommand and an argument. A marketplace install namespaces the command; both forms must behave the same. When the doctor’s closing line points at show or at turning the tool on, and when init replies that it is switched off, that follow-up uses the form the user typed. The help list, the mode line’s pointer at on, and the doctor’s request to run doctor again after a fault keep the non-namespaced spelling. The slash command is also registered in the host’s `/` menu by the shipped command file. It is a host menu document, not a program: after optional front matter, its body is the prompt template. The host inserts the user’s full argument string by expanding `$ARGUMENTS`, Claude Code’s published placeholder for that full string, in that body and submits the resulting prompt to this prompt-submit router. Forwarding holds when a level word in that string changes the stored level. A body without `$ARGUMENTS` does not forward: that invocation does not change the stored level, because the arguments are not placed in the command the router parses. This feature point is **operator control**. The contract those commands refer to is FP-04; the scoring they trigger is FP-01 and FP-02; cleanup referred to by `strict` is FP-03; the ledger they display is written by FP-05.

**Normal behavior:**

- Subcommands are exactly: `lite`, `full`, `strict`, `off`, `on`, `status`, `show`, `check`, `doctor`, `stats`, `init`, `help`. A bare `/prosecheck` (or `/prosecheck:prosecheck`) is help. An unknown word is reported as unknown and the list of valid words is given.
- `lite`, `full`, and `strict` store that level and confirm that the level was set. `off` stores `off` and confirms off. `on` stores `full` and confirms on (full). The phrases “stop prosecheck” and “prosecheck off” as the entire prompt (letter case ignored) also store `off`; the same words with anything else before or after them are an ordinary prompt.
- `status` reports the current level in one line.
- `help` lists every subcommand above except `help` itself, and the live level. It says that code, commits, configuration, and chat are always left alone. For each entry it says what the entry does: `lite` turns on the writing contract without scoring saved files; `full`, the default, adds the saved-file guard with its threshold of 40; `strict` lowers that threshold to 20 and adds the cleanup scrub; `off` and `on` switch the tool off and back on; `check` scores one file without changing it; `doctor` checks the install; `stats` reports the session's token figures and the score of the session's own prose; `init` exports the contract to `./AGENTS.md` for agents other than Claude Code. It also says that a deep rewrite is asked for in plain language with “prosecheck this” or “humanize this”.
- `check` takes a file path. It scores the file (FP-01, FP-02) and prints a report-only summary: the base name, the hook phrase, the score out of 100, the band, confidence (and reason when present), a coverage line, present only when the scan is truncated, that names the 262,144-character window and that only that prefix was included, and absent otherwise, and either a visible indication that no patterns fired or up to eight labels with hit counts. It states that this is a report only. It does not rewrite the file. Surrounding quotes and a leading `@` on the path (shell / completion artifacts) are stripped so the path still opens.
- `doctor` prints a titled health check with four check lines, each successful or faulty: (1) the current mode (`off` is not a fault of the install, but it is marked off and points at `on`); (2) whether the bundled detector is present; (3) whether Python ran the bundled detector — successful only when that run produced a numeric score, faulty when Python runs but the result is not a numeric score, and, when Python cannot be launched, faulty and telling the user that Python is absent, that the writing contract still applies to new prose, and that saved files will not be scored again until Python is available; (4) whether the settings folder is writable. The detector-present check stays successful when Python cannot be launched and says nothing about Python. A healthy install whose mode is not `off` therefore shows **four successful checks**. Then the closing line: when all four succeed and the mode is not `off`, it confirms the tool is active, names the 512 KB / 4 MB caps and the 262,144-character window, and names the `show` command as the place to see files that were only partly scanned or skipped; when any check is faulty, it asks the user to repair the faulty checks and names the `doctor` command to run afterwards; when the only issue is that the mode is `off`, it reassures the user that the install is healthy, tells them that saving files triggers no scoring in this mode, and names the `on` command.
- `show` lists this session’s ledger, newest first. An empty ledger says that no file has been scored in this session and that rows appear after prose files, including `.docx` and `.pdf` deliverables, are saved. A scored row shows the hook phrase, the score, the band, and the 262,144-character coverage note when truncated. When the row has pattern labels, it also shows whether the file was flagged or was under the threshold, and up to five of those labels. A scored row with no labels does not add that flagged-or-under clause. A size skip names the limit in kilobytes. A binary row says the file was not re-scored. A failed row says it was not scored and why. Ledgers of different session ids are separate. A ledger whose last modification is more than seven days old is not listed by a later session; one seven days old or younger is.
- `init`, when the level is not `off`, writes the writing contract into `./AGENTS.md` in the current working directory, wrapped in a prose-contract section with a section marker so a second `init` does not duplicate it. The exported contract is **portable**: it does not embed this machine’s install path or user name, and its text does not depend on the environment `init` runs in. Text already in `AGENTS.md` and outside the contract section is left in place. When the level is `full` or `strict`, the export tells the other agent how to resolve the bundled detector (the host’s plugin-root variable when set, otherwise locate `prosecheck`’s detector in installed skills/plugins). When the level is `lite`, that resolution paragraph is absent. If `AGENTS.md` already contains the marker, init reports that it is already present and does not duplicate the section. Independently, init copies the shipped Cursor rule to `./.cursor/rules/prosecheck.mdc` when that file does not yet exist; if it exists, init reports that the rule is already there and does not overwrite it. The Cursor rule’s front matter limits it to prose globs (`*.md`, `*.mdx`, `*.markdown`, `*.txt`, `*.rst`, `*.tex`, `*.org`, `*.adoc`) and does not include `*.py`, `*.js`, `*.ts`, or `*.json`. The rule body matches the prose-only scope and banned-vocabulary list of the writing contract in FP-04, and does not carry the post-write detector step. The current working directory is the project being exported; a relative payload working directory is not required because init runs where the user is.
- `stats` reads the session transcript the host named, or else the newest transcript (by modification time) under the config directory’s project folder; a named transcript wins over a newer one. It prints the current level, the count of assistant turns, the output-token total, and the cache-read input-token total — the totals taken from the transcript’s usage fields, not estimated, each labelled with its own quantity — and a session-prose score when there is enough assistant text. Only assistant entries count: any other entry contributes no turn, no tokens, and no text. Assistant entries that share one message identifier contribute one turn and one copy of their token totals, while the text of every one of them enters the prose slice; entries with no identifier are each counted. The prose slice joins the assistant entries’ text, removes fenced code, and keeps the last 40,000 characters; the session-prose score is printed only when that slice, with surrounding whitespace trimmed, is longer than 200 characters. A transcript that cannot be read yields no turn count and no token totals.

**Boundary / error behavior:**

- `check` without a path returns a non-empty reply that shows no score and is not the unknown-subcommand reply; its wording is the implementer’s choice. A path that is not a file, cannot be read, or is `.pdf` / `.rtf` is reported as not a file / cannot read / no readable text, without a score. A file over the 512 KB or 4 MB cap is reported as over that cap, in kilobytes. If Python is missing, check says the detector is unavailable and does not name a score. If a detector run exits without failure and produces no output, check names the file and says there was no report. A failed exit is not that case. If a detector run exits without failure and prints text that is not a report, check says there was no report and does not name the file. A failed detector exit makes check name the file and that failure. When the detector emitted failure text on its error stream, that text is the failure. When the failed run emits no text on its error stream, the reply still names the file and reports a failure. That report is not the no-report statement. Whether the reply contains the exit status is the implementer’s choice. Check never rewrites the file.
- `init` when the level is `off` writes **no** files: not `AGENTS.md`, not the Cursor rule. It tells the user the tool is off and names the `on` command as the way to allow the export.
- `init` that cannot read or write `AGENTS.md` or cannot write the Cursor rule reports that it cannot, and does not pretend the write succeeded.
- Unknown subcommands do not change the stored level.
- Command handling **blocks** the user prompt from being sent as an ordinary message: the hook returns a block decision whose reason is the command’s reply. Non-command prompts fall through to the reminder in FP-04.

## Cross-cutting obligations (all feature points)

- **Prose only.** Code, configuration, commits, and chat register are out of scope for the contract and the guard. The detector will score whatever text it is handed; the plugin must not hand it source files.
- **Local only.** No feature opens a network connection or sends document text off the machine.
- **Not authorship.** A score, a band, and a hook phrase describe writing. They do not name a person or a model as the author. Ethics text shipped with the product states this; the plugin’s user-visible phrases use “reads …” rather than “was written by …”.
- **Silence toward the user of the host agent.** The contract forbids narrating prosecheck in the agent’s replies. The guard’s nudge is extra context for the model, not a chat message the product itself prints to the user. `/prosecheck check`, `doctor`, `show`, `stats`, and `help` are the operator-facing reports; they speak only when asked.
